A plugin is a small Python program that adds a tool to the keyboard. It draws
a panel, reacts when the user presses things, and can type into the app the
user is writing in. With the user's say-so, it can also reach a website or
the user's AI model.

```python title="main.py"
from wm import plugin, ui

state = plugin.state(count=0)


def add():
    state.count += 1


def render():
    with ui.column():
        ui.title(f"Pressed {state.count} times")
        ui.button("Press me", on_click=add, primary=True)
```

That is a whole plugin, apart from a short `plugin.json`. You can write one on
the phone or in the browser, with a live preview beside the code:

<SettingsPath path="Tools / Plugins / Write a plugin" />

## What a plugin can do

- Draw its own panel from the keyboard's widgets, in the user's theme.
- Put text into the app: through an **Insert** button the user presses, or by
  typing with the `field.write` permission.
- Add buttons to the bar over selected text, which turn the selection into
  something else.
- Open from the Plugins tool, a toolbar tile, a key, the floating box, or a
  keyword like `@define rain`.
- Keep data on the phone, run timers while it is open, and have a settings
  page the app draws.
- With the user's permission: reach the websites it lists, ask the user's AI
  model, read the text being written when the user presses something in its
  panel, or read the clipboard.

Each permission is shown before install. The ones that can read the user's
things or send them away are [off until the user turns them on](/plugins/permissions/#risky-permissions).

## What a plugin cannot do

- **See what you type.** There is no key event API. A plugin cannot observe,
  change or delay a single keystroke going to your app.
- **Read the text you are writing in by itself.** Even with `field.read`
  allowed, a plugin reads the field only while it answers something you did in
  its panel, and never a password field or incognito text.
- **Reach the internet without you.** `network` is off until you allow it, and
  then reaches only the websites the plugin listed. Data saver stops it.
- **Reach Android.** No file paths, no reflection, no other apps. Only the named
  calls in the `wm` package.
- **Run in the background.** A plugin only runs while its panel or floating box
  is open. A reminder is a line of text the app shows; the plugin does not run
  for it.

:::note[These hold for every plugin]
No permission gets around them. See [Security](/plugins/security/) for how they
are enforced, and what the residual risks honestly are.
:::

Text still gets into a plugin: you type into its box, press **Paste** on it,
or select text and press one of its buttons on the selection bar. Results come
back out when you press **Insert** under a result, or in place of the
selection. Every one of those is a deliberate press, on a control the keyboard
drew.

:::tip[Turning plugins on]
Plugins are **off until you ask for them**. Turn them on with **Allow
plugins**. The first time, the app fetches the library that runs them, from
Google Play on a Play install and from the project's own data repository
otherwise. Then install one from the Addons screen, or open a `.wmplugin` file:

<SettingsPath path="Tools / Plugins / Manage plugins" />
:::

## Lua plugins were retired

Plugins were written in Lua until version 0.6.6, which replaced Lua with
Python. When you update to 0.6.6, every Lua plugin on the phone is removed,
since nothing is left to run it. The keyboard's plugin list and the Plugins
screen say which ones went.

What each one saved is kept. Install a Python plugin with the same id and its
data comes back as it was. The five demo plugins in the [addon repository](https://github.com/wasi-master/wmkeyboard-addon-repository) (Cipher Tool, UI Kitchen Sink, Todo List, Text Tools and Math Mode) kept their ids in the move, so
installing the Python **Todo List** brings your list back. Only what a plugin
saved with `wm.storage` is kept; its log and any reminders it had set are not.

Data that no plugin has claimed is listed on the Plugins screen, each with a
button to delete it now. Anything still unclaimed 90 days after the update is
deleted on its own.

<SettingsPath path="Tools / Plugins / Manage plugins" />

A Lua plugin file opened after the update is refused with a reason that says it
was written in Lua; [Lua is refused](/plugins/api-reference/#lua-is-refused) has
the exact rule.
