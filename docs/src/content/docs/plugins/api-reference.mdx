Everything a plugin can use. If it is not here, it does not exist.

## The manifest

`plugin.json`, at the top level of the archive.

| Field | Required | Meaning |
|---|---|---|
| `format` | yes | Always `"wmkeyboard-plugin"`. The one tag that identifies the file. |
| `version` | no | Container format version. `1`. |
| `id` | yes | Unique, lowercase, 3–64 characters of `a-z 0-9 . _ -`, starting alphanumeric. Becomes the plugin's folder on the device. Reverse-DNS by convention. |
| `name` | yes | Shown everywhere. Trimmed to 40 characters, control and direction-override characters removed. |
| `pluginVersion` | yes | Your version, e.g. `"1.2.0"`. |
| `author` | no | Shown on the install screen. |
| `description` | no | One or two sentences. |
| `apiVersion` | no | The API level you need: `3` for selection actions, `2` for `wm.reminders`, `ui.date` or `os.time(table)`, otherwise `1`. Left out, it counts as `1`. A higher number than the app knows is refused. |
| `entry` | no | The script inside the archive. Defaults to `main.lua`, or `main.py` for a Python plugin. |
| `permissions` | no | See [Permissions](/plugins/permissions/). Usually `[]`. |
| `actions` | no | Buttons on the bar over selected text. See [Selection actions](#selection-actions). Needs the `selection` permission. |
| `panel` | no | `false` for a plugin made of actions alone: it has no `render()` and is left out of the keyboard's plugin list. Defaults to `true`. |
| `language` | no | `"lua"`, the default, or `"python"` for a plugin made of actions alone. See [Python actions](#python-actions). |

:::note[Refused, not repaired]
A manifest this build does not fully understand is refused. That includes any
permission string it does not recognize. Half-understood code does not get to
run.
:::

## Your two functions

```lua
function render()    --> a widget, or a list of widgets
function on_event(e) --  optional
```

`render()` is called after loading and after every event. `on_event(e)` is
called when the user does something. Change your variables in `on_event`,
describe the result in `render()`.

Both are plain globals. There is no registration step.

## Selection actions

A plugin can add its own buttons to the bar that appears over selected text.
List them in the manifest, ask for the `selection` permission, and write one
more function:

```json title="plugin.json (excerpt)"
"apiVersion": 3,
"permissions": ["selection"],
"actions": [
  { "id": "rot13", "name": "ROT13", "summary": "Shift each letter 13 places", "icon": "lock" },
  { "id": "quote", "name": "Wrap in quotes" }
]
```

```lua
function transform(text, action) --> a string, or nil to leave the text alone
  if action == "rot13" then return rot13(text) end
end
```

When the user selects text and taps one of your buttons, the keyboard loads
your script in a fresh sandbox, calls `transform` with the selected text and the
action's `id`, and puts the string you return in place of the selection. Undo on
the bar takes it back. Nothing is kept between taps except what you write to
`wm.storage`: a global you set during one call is gone by the next.

| Action field | Meaning |
|---|---|
| `id` | Unique within the plugin, up to 32 characters of `a-z 0-9 _ -`. |
| `name` | The button's label. Trimmed to 24 characters. |
| `summary` | One line for the settings list. Optional. |
| `icon` | A key icon name, the same names a layout key takes (`lock`, `translate`, `link`). Optional; a plugin glyph otherwise. |
| `replaces` | `false` keeps the selection and adds your result after it. Defaults to `true`. |
| `input` | `"selection"`, the default, or `"none"` to be called with an empty string. |

Up to 16 actions. A call gets the same `wm` table as the panel, without
`wm.ui`, since there is no panel for it to write into. It has the same
instruction and time allowance as loading your script, because every tap loads
it. The user can switch each action off in
<SettingsPath path="Advanced / Selection actions" />, where actions from plugins
come after the built-in ones. They also appear in the **WM Keyboard** entry of
other apps' selection menus.

A plugin can have a panel and actions at once, the way the **Selection
actions** template keeps the quote style its action uses. One with actions and
no panel sets `"panel": false`.

### Python actions

A plugin whose `language` is `"python"` is made of actions alone. Its `entry`
(`main.py` by default) defines `transform(text)`, or `transform(text, action)`
when it has more than one action. It runs on a port of
[PyMini](https://github.com/anti-ltd/PyMini), the small Python interpreter Clink
uses: functions, comprehensions, f-strings, slicing, `try`, and the modules
`math`, `re`, `json`, `time`, `random` and `sys`. It has no `wm` table, so the
only permission it may declare is `selection`. This is how a
[Clink action](/reference/importing-other-keyboards/#clink-actions) installs.

## Widgets

Built by `ui.*`, which are pure-Lua helpers that return tables. You can write the
tables yourself if you prefer.

### Layout

```lua
ui.column { child, child, ... }   -- stacked vertically
ui.row    { child, child, ... }   -- side by side, equal widths
ui.spacer { height = 12 }         -- vertical gap, 0-64
ui.divider()                      -- a horizontal line
```

Children go in the array part, which is why they have no `name =` in front.

### Text

```lua
ui.label { text = "…", style = "title" | "body" | "caption" }
```

`body` is the default. Labels are not interactive and have no id.

```lua
ui.output {
  id = "result",
  text = "…",
  mono = false,        -- monospace, for anything with alignment
  insertable = true,   -- show the Insert button (default true)
  copyable = true,     -- show the Copy button (default true)
}
```

**`ui.output` is how your results reach the user's text.** The keyboard draws
Insert and Copy buttons under it. A tap on Insert puts the text where they are
writing. There is no function that types for them.

### Controls

```lua
ui.button { id = "go", text = "Go", style = "primary", enabled = true }
ui.toggle { id = "caps", label = "Uppercase", checked = false }
ui.input  { id = "msg", label = "Message", placeholder = "Type here" }
```

`style = "primary"` highlights a button. Anything else is plain. `enabled =
false` grays one out.

**`ui.input` carries no value.** The keyboard owns what is in the box: a tap
points the keys at it, and you are told the contents through an `input_changed`
event. Use `wm.ui.set_input(id, text)` to write to one. This is why a plugin
never sees a keystroke. It is handed the whole contents of its own box after
each one, and nothing else.

### Tabs

```lua
ui.tabs {
  id = "modes",
  ui.page { title = "First", child, child },
  ui.page { title = "Second", child },
}
```

Top level only, up to 8 pages. Which page is showing is the keyboard's business.
You get a `tab_selected` event if you care.

### Date

```lua
ui.date {
  id = "due",
  label = "Due",
  value = due,     -- seconds, as os.time() gives, or nil for no date yet
  time = true,     -- pick a time of day too (default false)
  step = 15,       -- minutes the smaller time buttons move, 1-60 (default 15)
}
```

The keyboard draws the date between a back and a forward arrow, the time (with
`time = true`) between buttons that move it by `step` minutes and by an hour,
and **Today** and **Clear** under them. With no `value` it shows **Set date**,
which picks today, or the next whole hour when `time` is on.

Like `ui.input`, the widget keeps nothing. Each press sends a `date_changed`
event with the new value, and the next render draws whatever you kept. Without
`time` the value is the start of a day. Days move on the calendar in the phone's
time zone, so 9:00 stays 9:00 across a clock change.

### Progress

```lua
ui.progress()   -- an indeterminate bar
```

## Events

`on_event(e)` receives a table. Always `e.type` and `e.id`. Some carry more.

| `e.type` | Extra | Fired when |
|---|---|---|
| `"click"` | none | A button was tapped. |
| `"toggle"` | `e.value` (boolean) | A toggle was flipped. |
| `"input_changed"` | `e.value` (string) | The contents of one of *your* boxes changed. |
| `"tab_selected"` | `e.index` (number, 0-based) | A tab was picked. |
| `"date_changed"` | `e.value` (number of seconds, or `nil`) | A date widget moved, or was cleared. |

`tab_selected` counts from 0, not from 1 the way the rest of Lua does. The
first page is 0.

`input_changed` fires per keystroke into your own input widget. That is how a
live preview works. It is bounded to your panel: you are told what is in your
box, never what is typed anywhere else.

## `wm.*`

The complete host API.

### Always available

```lua
wm.api_version      -- 2
wm.plugin_id        -- your manifest id
wm.plugin_version   -- your manifest pluginVersion
wm.log(message)     -- a line in your log, readable in Settings
```

```lua
wm.ui.set_input(id, text)   -- write to one of your own input widgets
```

Applied after your handler returns. Capped at 8 KB.

```lua
wm.json.decode(text)   --> table, or nil + reason
wm.json.encode(value)  --> string, or nil + reason
```

A Lua table encodes as a JSON array when its keys are exactly `1..n`, and as an
object otherwise. Whole numbers stay whole. Depth is capped, which is also what
stops a self-referencing table from encoding forever.

### With the `storage` permission

```lua
wm.storage.get(key)      --> string, or nil
wm.storage.set(key, val) --> true, or nil + reason
wm.storage.remove(key)
wm.storage.keys()        --> list of strings
```

Strings only, so use `wm.json` for anything structured. Local to your plugin,
local to the device, deleted when the user uninstalls you. `set` returns `nil`
and a reason when you are over quota. Say something rather than losing the data
silently.

If the manifest did not declare `storage`, `wm.storage` is `nil`.

### With the `reminders` permission

```lua
wm.reminders.set(id, time, text) --> true, or nil + reason
wm.reminders.cancel(id)          --> true when there was one
wm.reminders.list()              --> { { id = ..., time = ..., text = ... }, ... }
```

At `time`, in seconds as `os.time()` gives, the app shows `text` in a
notification with your plugin's name as its title. Setting an `id` that is
already set replaces it. `list` gives every reminder not yet shown, soonest
first; a reminder leaves the list once it is shown.

Your script does not run to show it. The app keeps the id, the time and the
text, and posts the notification itself, so a reminder fires with the keyboard
closed. It does not fire while plugins, or your plugin, are switched off; a
reminder that comes due then is dropped.

`set` returns `nil` and a reason for a time already past, for empty text, or
past 64 reminders. Text is cut to 200 characters, with control and
direction-override characters removed.

If the manifest did not declare `reminders`, `wm.reminders` is `nil`. A plugin
can check for that and work without it.

### Not present, and never will be

`wm.text`, `wm.clipboard`, `wm.http`, `wm.net`, `wm.files`. None of these exists.
There is no API for reading what the user types, reading the field, reading the
clipboard, or reaching the network. See [Security](/plugins/security/).

## The Lua you get

Lua 5.2 via [LuaJ](https://github.com/luaj/luaj), with these libraries:

**Available:** `string`, `table`, `math`, `bit32`, the base functions (`assert`,
`error`, `getmetatable`, `setmetatable`, `ipairs`, `pairs`, `next`, `pcall`,
`xpcall`, `rawget`, `rawset`, `rawequal`, `rawlen`, `select`, `tonumber`,
`tostring`, `type`, `_G`, `_VERSION`), `print`, and a reduced `os`.

**`os`** has `os.time()`, `os.clock()` and `os.date(format, time)`. Given a
table, `os.time { year = 2026, month = 10, day = 20, hour = 9 }` is that moment
in the phone's time zone. `hour` defaults to 12, `min` and `sec` to 0, and a
field past its range rolls over, so `day = d + 1` on the last of the month is
the first of the next. `os.date` takes `"*t"` and a strftime subset
(`%Y %y %m %d %H %M %S %j %p %A %a %B %b %c %x %X %%`), plus a leading `!` for
UTC. Nothing else: no `getenv`, `execute`, `exit`, `remove`, `rename` or
`tmpname`.

**Absent:** `io`, `require`, `package`, `coroutine`, `debug`, `luajava`, `load`,
`loadstring`, `loadfile`, `dofile`. You cannot load code at runtime, and
precompiled Lua is refused at install.

**`collectgarbage`** exists but does nothing and returns 0.

:::note[One incompatibility worth knowing]
Adding to the `string` table works for `string.mine(s)` but not for `s:mine()`.
Method syntax resolves through a process-wide table that is frozen so one plugin
cannot rewrite string handling for every other one.
:::

## Limits

Exceeding one of these is something you can see: either an error, or a note on
the panel saying what had to be dropped. Two are quiet, and the table says which.

| | |
|---|---|
| Script size | 256 KB |
| Archive size | 1 MB, 16 entries |
| Instructions | 30M on load, 20M per event, 4M per render, 30M per selection action |
| Time | 3 s on load, 2 s per event, 0.5 s per render, 3 s per selection action |
| Selection action result | 64K characters |
| Widgets | 256 nodes, 12 deep, 8 tabs *(dropped, and reported)* |
| Widget text | 2 KB per node, 64 KB per tree *(truncated, and reported)* |
| `string.rep` output | 256 KB |
| Pattern subject / pattern | 256 KB / 256 bytes |
| `table.concat` output | 1 MB |
| Storage | 128 keys, 64 chars per key, 8 KB per value, 64 KB total |
| Reminders | 64 pending, 64 chars per id, 200 chars of text, up to ten years ahead |
| Log | 200 lines of 512 characters *(truncated quietly)* |
| Input box | 8 KB *(truncated quietly)* |

A plugin that runs out of instructions or time is stopped, the user is told, and
it takes a strike. So does one the watchdog has to abandon for going
unresponsive. Two strikes and the plugin is switched off until they turn it back
on, which also forgives the strikes. That last part is a setting: **Switch off a
plugin that hangs**, on the Plugins screen, on by default. With it off the
strikes are still counted and still shown, and only the automatic switch-off
goes away.
