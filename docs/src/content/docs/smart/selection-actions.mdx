Selecting a phone number in a chat and then dialling it usually means copying it, leaving the app, opening the dialler and pasting. The keyboard already knows what you selected, so it can offer the things that shape of text is for, and a good deal more: the everyday edits, a find and replace, line tools, case and chat formatting, conversions, and a way to hand the text to your contacts, maps or calendar.

Select `01712345678` and the bar reads **Select all, Call, Message, WhatsApp, Contact, Copy, Cut, Paste, Delete, Share, Format, Find, Replace**. Select a sentence and it reads **Select all, Copy, Cut, Paste, Delete, Share, Save as note, Format, Find, Replace, Repeat, Grammar, AI, Bangla, Fancy** and so on, with the actions that only make sense for what you selected (Sort on several lines, Colour on `#336699`, Zones on `5pm`) appearing when they do.

This is off by default. It adds a bar that appears out of a gesture you already make for other reasons, so you have to ask for it.

The same actions, with translation and the AI actions beside them, are also in the menu most apps show over selected text, with no keyboard open and nothing to switch on. See [In any app's selection menu](#in-any-apps-selection-menu).

## Turning it on

<SettingsPath path="Advanced / Selection actions" />

Turn on **Selection actions**. Select some text in any app. The bar appears while the selection is live and goes away when you clear it.

To switch it on and off without opening settings, add the **Selection actions** tool to your toolbar. One tap flips the same switch, and a message says which way it went. Text that is already selected gets its bar straight away.

## In any app's selection menu

The bar lives in the keyboard, so it only sees text in a box you are typing into. For text anywhere else (a web page, a message someone sent you, an email), select it and pick **WM Keyboard** from the menu that appears over the selection, the one with Copy and Select all. On some phones it is behind the menu's three dots, and some apps leave it out of their menu altogether (see [When the entry is missing](#when-the-entry-is-missing)). You do not have to be typing with this keyboard, and the bar does not have to be on.

A sheet opens over the app with the text at the top and the actions under it, in three groups:

- **Language.** **Translate** puts the text into the language the [Translate](/tools/translate/) tool translates into, through the engine and services you set up there. Each of your [AI actions](/tools/ai/) follows it (Explain, Summarize, Formal and the rest, your own included) and writes its answer in place of the text. **Ask AI** opens the [AI chat](/tools/ai-chat/) with the text attached, and **Look up** opens the [Look up](/tools/look-up/) card on it.
- **Rewrite.** The actions from this page that change text without needing a text box: Format and its case options, Fancy, Sort, Unique, Number, Bullets, Check boxes, Digits, Zawgyi ⇄ Unicode, JSON, Base64, Decode and Remove trackers.
- **Open in.** Call, Message, WhatsApp, Email, Open, Contact, Map and Calendar, for a phone number, an address, a link, a place or a date.

The rewrites and the Open in actions come from the same **Actions** list as the bar, in the same order (see [Options](#options)), and each shows only where it applies. Translate needs the Translate tool switched on. The AI actions need the AI tool switched on and set up, with a provider or a downloaded model.

Each action works on the text as the last one left it, so you can translate a paragraph and then make it shorter, or sort lines and then number them. The arrow at the bottom left undoes one step at a time. Then:

- **Replace** puts the result in place of your selection. The app does the replacing, so it works in any app whose text box offers the menu.
- **Copy** copies the result and closes the sheet. On text you cannot edit, such as a web page, there is no Replace, and Copy is the way to take the result with you.
- The share button beside Undo hands the result to another app.

Calendar opens your calendar app's editor here rather than the keyboard's own [Calendar tool](/tools/calendar/), since there is no keyboard open to show it in. The sheet leaves out the bar actions that work on the text box itself (Select all, Copy, Cut, Paste, Delete, Find, Replace, Move up, Move down), the ones that need a keyboard panel or the keyboard's loaded dictionaries (Bangla, Banglish, Hindi, Hinglish, Grammar, DeepL Write, Repeat, QR, Search, Speak, Zones, Colour, Save as note, Edit word), and chat formatting, which depends on the app you are typing in.

Nothing in the sheet is stored. Translate sends the text wherever the Translate tool sends it, which is nowhere when it translates on the phone. The AI actions do the same with the AI tool's provider, and [Data Saver](/privacy/data-saver/) holds them back on mobile data as it does in the keyboard: when it is set to ask, the sheet says so, and tapping the action again sends it.

### WM Translate

For translating alone, turn on **WM Translate in the selection menu**. It adds a second entry that opens the same sheet with the translation already running. It ships off, because every entry is one more row in every app's menu and Translate is a single tap inside the WM Keyboard sheet anyway. The entry is only there while the Translate tool is switched on.

### Choosing the entries

<SettingsPath path="Advanced / Selection actions" />

The group **In other apps' selection menus** has a switch for each entry the keyboard adds to other apps' menus:

| Entry | Switch | Default |
|---|---|---|
| WM Keyboard | WM Keyboard in the selection menu | On |
| WM Translate | WM Translate in the selection menu | Off |
| Ask AI | Ask AI in the selection menu | On |
| Look up | Look up in the selection menu | On |

Ask AI and Look up are the same switches as on the [AI tool](/tools/ai/#options) and [Look up](/tools/look-up/#options) pages, repeated here so all four sit in one place. Turning a switch off takes its entry out of every app's menu. Turning off the Translate or AI tool takes their entries out too. These switches do not depend on **Selection actions** at the top of the screen, which is the keyboard's own bar.

### When the entry is missing

Not every app lists WM Keyboard, Ask AI or Look up in its selection menu, even with every switch above on. The menu is put together by the app you are in, and since Android 11 an app can only see the other apps on the phone it has asked to see in its own manifest. Chrome is allowed to see every app on the phone, so the entries are always in its menu. Other apps see WM Keyboard only when something they asked to see happens to cover it, and that varies from app to app: on one test phone Gmail and WhatsApp could see it, while Telegram and Google Keep could not. An app that can't see it builds its menu without the entries, and other apps' entries go missing along with WM Keyboard's: Google Translate, ChatGPT, a dictionary. Some apps also draw a menu of their own that has no place for other apps' entries at all.

Where the entries are there, they can be the last ones in the list behind the three dots, after Ask Gemini, Read aloud and whatever else your apps add. Scroll that list before deciding they are missing.

Nothing on WM Keyboard's side puts the entries back in such an app. Turning the switches off and on, reinstalling, or typing with WM Keyboard in that app leaves its menu as it was. Only that app's developer can add the request.

The keyboard's own bar works in every app, because the keyboard reads the selection itself rather than waiting for the app's menu. Turn on **Selection actions** (see [Turning it on](#turning-it-on)), select text in a box you are typing into, and the bar offers Translate, AI and the rest. For text you cannot type into, the [floating button](/reference/settings/floating-button/#asking-the-ai-about-the-screen) can ask the AI about the screen or look up a tapped word, outside the Play Store build. Copying the text and pasting it into a box, where the bar can reach it, works everywhere.

## What the keyboard reads

The keyboard reads your selection as a whole. That is the rule behind every result on this page, and it is deliberate:

- `01712345678` is a phone number.
- `call me on 01712345678 tomorrow` is plain text. You selected the sentence, not the number in it.
- `example.com/page` is a link. `report.txt` is not, because `txt` is not one of the endings a bare domain is allowed to have.
- Two lines are never one thing, whatever the pieces look like on their own.

Pulling a fragment out of a longer span is a different job, and the [clipboard](/tools/clipboard/) already does it. That surface has the room to show you what it found and where it found it. This one does not, so it does not guess.

Phone numbers use the same formats as the clipboard, under [Phone formats](/reference/settings/phone-formats/). With a format saved, a number has to match it, which is what keeps an invoice total or a row of figures from offering to dial itself. With no format saved, the plain shape rules apply.

On top of that reading, a few actions look at what the text holds: whether it has several lines, Bengali or Latin letters, digits in another script, a colour code, a date or time, a place. Those checks are cheap, and the dearer ones (dates, places) only run while an action that needs them is switched on.

## The bar

The bar is one row of chips that scrolls sideways, in an order you control under **Actions** (see [Options](#options)). Every action is drawn only where it applies, so the row you see is shorter than the list: Call never appears on a sentence, Sort never appears on a single line.

Two things sit outside the order. **Undo** is always first while there is something to undo. And the actions whose answer is a pick rather than a single result (Format on text, Fancy, Colour, Zones) open a short row of choices in place of the bar, with an arrow on the left to come back.

## Undo

Every rewrite the bar makes (a case, a style, a chat marker, a grammar fix, a conversion, a replace) is remembered while the selection stays live. **Undo** is the first chip whenever there is one, and each tap walks one step back: lower case, then Title Case, then bold, then three taps of Undo returns the original.

The memory ends with the selection. Move it onto other text, clear it, or leave the field, and there is nothing left to put back. Before putting anything back the keyboard checks the field still reads as the last rewrite, so an edit you made in between is never overwritten. Cut and Delete take the selection away and are not undone here; your editor's own undo covers those.

## Editing

**Select all** selects the whole field. A long press usually selects only one word, so this is the fast way to act on everything you wrote. In a web page it goes in as Ctrl+A, so an editor in the page, like a code editor that only draws the lines on screen, selects its whole text itself rather than losing a selection the keyboard made for it. **Copy**, **Cut** and **Paste** are the editor's own; Paste replaces the selection and only appears while the clipboard holds text. **Delete** removes the selection. **Share** opens the [share sheet](/reference/settings/share-sheet/) with the selected text, or Android's when the keyboard's sheet is off. **Save as note** keeps the selection in the [Notes tool](/tools/notes/) as a new note, or adds it to the note you edited last when <SettingsPath path="Tools / Notes / Save as note from a selection" /> says so; a toast says which. It appears only while the Notes tool is enabled.

## Find and replace

**Find** jumps to the next place the selected text appears, wrapping round to the top, and keeps it selected so the bar stays and a second tap walks on. The match is brought into view, even in an editor that would leave it under the keyboard or off the screen.

**Replace** opens the [Find & replace](/tools/find-replace/) panel above the keys, the same one its toolbar tool opens, with two fields: what to find, already holding the selection, and what to replace it with. Tap a field and type into it; the keys go to the panel, not to the app. The current match is selected in the field itself, where you can see it, and the panel says which one of how many. Enter in the find field goes to the next match; Enter in the replace field replaces the current one.

<PhoneFrame caption="The Find and replace panel: two fields, the toggles, the buttons and the count.">
  <Shot id="smart/selection-actions-replace" alt="The Find and replace panel: two fields, the toggles, the buttons and the count." />
</PhoneFrame>

Three toggles: **Aa** matches case, **[ab]** matches whole words only (in any script, so a Bengali word is a whole word too), and **.\*** reads the find field as a regular expression, with `$1` in the replacement standing for the first group. A pattern that is not valid says so under the toggles, and one that takes too long on the text is stopped rather than left to hang.

**Replace** swaps the current match and moves to the next. **All** replaces every match in one go, which Undo takes back in one go too. A field that does not report where its text is (a few web views) still lets you find, but not replace in place.

**Repeat** opens the [Text repeat](/tools/utilities/#repeating-text) panel with the selection as the text to repeat: pick a count and a separator there and Insert writes the copies at the cursor. It appears only while the Text repeat tool is enabled.

## Lines

With two or more lines selected, four chips appear. **Sort** puts them in order, digits compared as numbers so `item2` comes before `item10`; sort a list that is already in order and it turns the other way round. **Unique** drops repeated lines. **Number** puts `1.`, `2.`, `3.` in front of each line, and **Bullets** a bullet. **Check boxes** puts `☐` in front of each line, a list to tick off. All three are toggles: a list that already has the prefix on every line loses it, and any one converts into the others, so a bulleted list becomes a numbered one in a tap. A ticked box (`☑`, `✅`) and a Markdown task box (`- [ ]`, `[x]`) count as boxes already.

**Move up** and **Move down** swap the lines your selection touches with the line above or below, and the selection goes with them, so pressing again keeps moving them. They work on one line as well as several, which is how a single item in a list changes places with its neighbour. Both are off to start with; turn them on under Actions.

## Format

**Format** rewrites the selection in place. What it does follows what the selection is:

- **A phone number** is written back in your own saved format. If you keep `+880 1XXX-XXXXXX`, then `01712345678` becomes `+880 1712-345678`. The separators come from the format you wrote, not from a shape the keyboard invented. With no format saved, a number that names a country code becomes E.164 (`+8801712345678`) and any other number becomes its bare digits.
- **A link** loses its tracking parameters. `utm_*`, `fbclid`, `gclid`, `igshid` and about twenty others go; everything else in the query, the path and the fragment stay exactly as they were. A link with no scheme gains `https://`.
- **An address** is lower-cased.
- **Anything else** opens the case options instead.

The Format chip is left off when the rewrite would change nothing. A number already in your format, or a link with nothing to strip, does not get a button that does nothing.

### Case options

On ordinary text, Format opens a row of chips in place of the bar: **lower case**, **Title Case**, **UPPER CASE** and **Sentence case**, plus, when you switch them on under Actions, the programmer's cases **camelCase**, **snake_case**, **kebab-case** and **CONSTANT_CASE**. Those four read their input in any convention, so `Hello World`, `hello_world` and `helloWorld` all mean the same two words. The arrow on the left goes back to the actions.

<PhoneFrame caption="Format on plain text: the case options, with the arrow back to the actions.">
  <Shot id="smart/selection-actions-case" alt="Format on plain text: the four case options, with the arrow back to the actions." />
</PhoneFrame>

Each one rewrites the selection and leaves the result selected, so you can try Title, then Sentence, then UPPER without reselecting between taps. None of them changes the spelling: UPPER CASE writes `ß` as the capital `ẞ` rather than `SS`, so lower case gets the word back exactly.

Title case and Sentence case leave a word that is already all capitals alone, so an acronym in the middle of a sentence survives. `the NASA launch` becomes `The NASA Launch`, not `The Nasa Launch`. That rule is suspended when the whole selection is capitals, because somebody selecting `HELLO THERE` and reaching for Title case is fixing shouting, not protecting acronyms.

**Fancy** opens the [Fancy Text](/languages/fancy-text/) styles, each chip written in itself, and restyles the selection in the one you pick.

## Chat formatting

**Bold**, **Italic**, **Strike** and **Mono** wrap the selection in the markers the app you are typing in understands, and a second tap takes them off again. They only appear in apps whose syntax the keyboard knows, because markers an app does not read arrive as punctuation:

| Apps | Bold | Italic | Strike | Mono |
|---|---|---|---|---|
| WhatsApp, Viber | `*text*` | `_text_` | `~text~` | `` ```text``` `` |
| Slack, Google Chat, Messenger, Rocket.Chat | `*text*` | `_text_` | `~text~` | `` `text` `` |
| Threema | `*text*` | `_text_` | `~text~` | none |
| Telegram | `**text**` | `__text__` | `~~text~~` | `` `text` `` |
| Discord, Element, Beeper, Reddit, Mattermost, Zulip, GitHub | `**text**` | `*text*` | `~~text~~` | `` `text` `` |

Mono on several lines uses the app's fenced block where it has one. These four are off to start with; find them under Actions.

## Convert

- **Digits** turns figures in another script into `0` to `9`: `০১৭১২` becomes `01712`, and Devanagari, Arabic-Indic or Persian figures the same.
- **Colour** appears on a colour code (`#336699`, `#f00`, `0xFF336699`, `rgb(51, 102, 153)`, `hsl(210, 50%, 40%)`), wears a swatch of the colour, and opens its other spellings; tap one to write it in place.
- **JSON** pretty-prints a minified object or array with two-space indents, or minifies a pretty one. Key order and number literals survive either way.
- **Remove trackers** appears on a link that carries tracking parameters (`utm_source`, `fbclid`, `gclid`, `si` and the like) and takes them off, leaving everything that says which page it is. `youtu.be/abc?si=XyZ` becomes `youtu.be/abc`. It also takes the trackers a known site adds only there, such as Amazon's `/ref=…` path or X's `?s=20`, and turns a redirect link such as Google's `/url?q=…` into the link it leads to. It also shows on a sentence or a paragraph with such a link in it, and cleans every link there while leaving the words alone, and on a single link of any length (before version 0.6.2 a link longer than 320 characters, which tracked links often are, never offered it). Add parameter names of your own under <SettingsPath path="Clipboard / Copy rules" />, where **Remove trackers from copied links** also cleans every link as you copy it. It is on to start with; if you have already picked your own set of actions, switch it on under Actions.
- **Zawgyi ⇄ Unicode** appears on Burmese text and converts it between Zawgyi, the old font encoding much Burmese is still written in, and Unicode, whichever way the text needs: Zawgyi becomes Unicode and Unicode becomes Zawgyi. It reads the whole selection to decide, and writes the result exactly as converted even in a text box the keyboard is [writing Zawgyi](/languages/burmese/#writing-zawgyi) into. It is on to start with; if you have already picked your own set of actions, switch it on under Actions.
- **Base64** decodes Base64 text, and **Decode** a percent-encoded link (`hello%20world` to `hello world`). Both are careful about what counts: an ordinary word is never mistaken for Base64, and `50% off` is not encoded.

## Language

- **Bangla** turns Banglish into Bengali script, word by word: the spelling map first (`tmr` to তোমার), then the same phonetic reading the suggestion strip uses, which is what lets `asi`, `achi` and `achhi` all land on আছি, and only then a literal transliteration. Digits and punctuation stay as they were. It appears on Latin text while Bengali is one of your languages.
- **Banglish** goes the other way, writing Bengali script back in Latin letters by pronunciation (তোমার to `tomar`, ধন্যবাদ to `dhonnobad`, কী to `ki`), with the most readable spelling from the map for words it knows.
- **Hindi** does the same for Hinglish: the known-spellings list first (`theek` to ठीक, `nhi` to नहीं), then the downloaded Hindi word list through the same phonetic match the strip uses, then the rules. It needs the Hindi phonetic layout switched on, because that is what loads all three. On Latin text with both Bangla and Hindi available you get both chips, and you pick the language you wrote.
- **Hinglish** writes Devanagari back in Latin letters the way it is said, not the way it is spelled: करना is `karna` and नमस्ते is `namaste`, because spoken Hindi drops the inherent vowel in the first and keeps it in the second. Long vowels are doubled inside a word and single at its end (`naam`, `theek`, `mera`, `ladki`).
- **Grammar** runs the [Grammar](/smart/grammar/) checker over the selection alone and commits every suggestion at once, offline with Harper. With [LanguageTool](/smart/grammar/#checkers-harper-and-languagetool) switched on, the selection goes to its server when LanguageTool is the checker for your language, and never from a password field or in incognito. It shows a spinner while it works and says so when there is nothing to fix.
- **DeepL Write** sends the selection to DeepL Write and puts DeepL's rewrite in its place, in the [writing style](/tools/translate/#options) you picked. It shows only after you add a DeepL API Pro key and turn on **DeepL Write** under Tools / Translate, and it works in the F-Droid build too. Undo brings the original back.
- **AI** opens the [AI](/tools/ai/) tool on the selection. Under **AI buttons** you can give any AI action a chip of its own (Formal, Shorter, Friendly and Summarize are made for it): one tap runs it on the selection and the result lands in the AI panel, ready to apply. Applying replaces the selection, not the field around it. The AI's own Translate action reads **AI translate** as a chip, so it is not confused with the Translate chip below.
- **Translate** opens the [Translate](/tools/translate/) tool with the selection in its box and the translation under it, using the translation engine you picked there (online, or on the device). **Replace text** in the panel then replaces the selection, not the field around it. It sits just before AI on the bar and is on to start with; if you have already picked your own set of actions, switch it on under Actions. Opening the Translate tool from the toolbar with text selected does the same thing.

## Look up

**Edit word** appears when the selection is one word and opens that word's [word card](/smart/personal-dictionary/#from-the-suggestion-strip), the same card that holding a word on the suggestion strip reaches through **Edit**. It shows where the keyboard found the word and how often you typed it, and carries Never suggest or Suggest again, Delete, the rank controls, the spelling and **Keep these capitals**. **Add** is about the selected word: it appears while that word is not in your personal dictionary, and adds it spelled as selected. Punctuation around the word does not count, so `"Hello,"` and `(don't)` are single words; `two words`, `2026` and `e.g.` are not. The card works on your dictionary, not on the text, so the selection stays as it was. It closes when the selection moves to other text or goes away. If you have already picked your own set of actions, switch it on under Actions.

**Search** opens the [web search](/tools/search/) tool with the selection as the query. **Speak** reads the selection aloud with the phone's speech engine, or with a downloaded [offline voice](/tools/read-back/#offline-voices) for that language (in Bengali for Bengali text), and turns into Stop while it does. **Zones** appears on a time and shows it in each of the zones you picked under Time zones, UTC and your own to start with; tap one to write it in place of the selection. A selected `now` or `time now` counts as a time too, the current one, so selecting it gives the time in each zone right now.

## Open in

**Call** and **Message** open your dialler and your messaging app with the number filled in. **WhatsApp** opens a chat with that number. **Contact** adds the number or address to your contacts. **Open** hands a link to your browser, and an address to your mail app. When the link belongs to an app instead (a YouTube link with YouTube installed, say), the chip wears that app's icon and a small outward arrow, so you know where the tap goes before you make it. **Email** writes a new message to the selected address. **QR** opens the [QR generator](/tools/utilities/) with the link already in it. **Map** opens coordinates (`23.8103, 90.4125`) or something that looks like a street address in your maps app. **Calendar** adds a selected date or time (`14 Sep 2026`, `tomorrow 5pm`, `১৪ সেপ্টেম্বর`) as an event: the [Calendar tool's](/tools/calendar/#adding-an-event) composer opens with the selection as the title and that date and time set, ready to save. With the Calendar tool switched off, or its **Save events** set to the calendar app, it opens your calendar app's editor instead.

None of these send anything anywhere themselves: each hands the text to an app you picked and stops.

## Where the bar draws

<SettingsPath path="Advanced / Selection actions / Where it appears" />

**Own row** is the default. The bar gets a row of its own above the keys, which arrives with the selection and leaves with it. The keyboard is one row taller while it is there, and the app is asked to scroll the selected line back into view as the row opens, so the text you are working on does not end up behind the keyboard. That row is reorderable like any other under [Rows & bars](/reference/settings/rows/), so you can put it above or below the suggestion strip. While a panel such as Clipboard or Emoji is open, the row stays away: text selected under an open panel no longer makes the keyboard grow, and the row arrives when the panel closes.

**Suggestion strip** puts the actions over the strip instead, which costs no height at all. There are no word suggestions to show while text is selected, so the strip has nothing to give up. With a panel open the strip goes back to the toolbar, because the arrow on that row is how you get out of the panel.

**Show on every selection** keeps the bar up on a selection too long to read. The keyboard does not read a selection past about 4,000 characters, so by default such a selection takes the whole bar away, Copy and Paste included, even though neither of those ever needed the text read, because the app does that work itself. Turn this on and the bar stays, carrying Select all, Copy, Cut, Paste and Delete, whichever of them you have switched on. Everything else still waits for a shorter selection, since every other action begins by reading the text.

**Show with nothing selected** keeps the bar's row on screen all the time, not only while text is selected. With just a caret in the field, the row holds Select all and Paste, whichever of them you have switched on. Tap Select all and the full row for the whole text replaces it, so Copy, Translate and the rest are one tap further on and you never have to long-press to select first. The keyboard stays the same height as you move between selecting and typing. This switch only exists with **Own row** picked: over the suggestion strip it would take your suggestions away while you type, so it is hidden there. Password fields still never show the row.

**Read what is selected** is the entity half of the feature. Turn it off and every selection is read as plain text: you keep the edits, the case options and the conversions, and lose Call, Email, Open, QR and Contact. It is worth turning off if you find the guesses wrong more often than right, since the generic half is the half that always applies.

**Actions** is the list of everything the bar can offer, grouped, searchable, each with its own switch, and with a pencil that lets you drag the actions that are on into the order you want. The full list is on the [settings reference](/reference/settings/selection-actions/).

**Icon only** picks the actions drawn as their icon with no name, for a shorter row once you know them by sight.

## Details and edge cases

- **The bar never appears over a password field.** Putting a password in front of a Share chooser is the mistake this feature should not make.
- **An action is only offered when it can work.** WhatsApp is hidden when WhatsApp is not installed. Search, Translate, QR, Grammar and AI are hidden when their tools are switched off, which includes the tools that [power saving](/typing/power-saving/) and the lock screen have already taken away, and AI is hidden until a provider is set up. Hiding a tool from the toolbox is not switching it off: turn off **Show in toolbox** on the tool's own page to keep, say, the AI chip here while the AI tool stays out of the toolbox grid.
- **Nothing is stored and nothing is sent by the keyboard.** Every action either edits the field you are already in, or hands the text to an app you picked. Grammar and the Bengali conversions run on the device. The one exception is DeepL Write, which you set up yourself: it sends the selection to DeepL.
- **Before your first unlock**, only the actions that touch the current field survive: the edits, the rewrites and Find. Paste needs a clipboard that is still locked, Speak needs a speech engine, Edit word needs the personal dictionary, which is locked too, and everything under Open in would have to start another app.
- **A very long selection gets only the actions that need no reading.** Past about 4,000 characters the keyboard stops reading the selection, so the case options, the rewrites and the entity actions all stand down. With **Show on every selection** off, which is how it ships, the bar goes away entirely and the toolbar's own [Copy tool](/tools/text-editing/) is the answer; with it on, Select all, Copy, Cut, Paste and Delete stay on the bar, because the app does their work and the length costs them nothing.
- **The bar follows the selection, not the caret.** Extending a selection with [selection mode](/tools/text-editing/#selection-mode) or a [trackpad](/tools/trackpad/) drag re-reads it as you go, so the actions change under your finger as the selection grows into a whole phone number.
- **This version resets the list of actions once.** The list grew from thirteen actions to forty-five, and the shipped choices replace whatever you had picked before, so the new actions are there. Anything you switch off after that stays off.
