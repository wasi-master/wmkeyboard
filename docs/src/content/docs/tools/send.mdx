The **Send files** tool moves a file out of the keyboard in two ways. **Link** encrypts the file on your phone, uploads it to a [Send](https://github.com/timvisee/send) server (the maintained fork of Firefox Send) and gives you a link with an expiry, a download limit and an optional password. **Nearby** hands the file to a phone or computer next to you over Wi-Fi, with no server at all. It receives both kinds too: a Send link in a chat gets a chip that downloads and decrypts the file, and a device nearby can send a file to you.

## Sending a link

1. Open the tool and pick what to send: **Files** opens the keyboard's [file manager](/tools/files/) (Android's document picker in the Play Store build), **Gallery** opens the [Gallery](/tools/gallery/) tool to pick photos and videos, **Clipboard** takes what you copied (a file, a picture, or text saved as a file), and **Field text** saves the text in the field you are typing in.
2. Choose how long the link lives and how many times it may be downloaded. The chips show what the chosen server allows. Add a password if you want one; **Generate** makes a twelve-character one you can read out.
3. Press the upload button. The ring fills as the file is encrypted and uploaded in one pass. When it is done the link is typed into the field, or copied, or shown with its QR code, whichever you chose under **After the upload**. Hold the button instead to pick for this one upload.

The file is encrypted before it leaves the phone, with a key that travels only in the link, after the `#`. The server stores the ciphertext, its size and when it arrived. It never sees the key, the file or even its name, which is encrypted too. Anyone with the link can download the file until it expires or the downloads run out; a password is a second lock the server checks on top.

A finished link stays in the panel with **Insert**, **Copy**, **Share** and **QR code**, and **Manage** lets you change the download count or delete the file from the server early. **History** lists every link this phone made, with how long each has left and how many downloads were used, and the files you received.

## Receiving a link

Paste or type a Send link in any field and a chip appears on the suggestion strip: **Receive the file**. Copy a link in another app and the same chip is waiting when you come back to the keyboard. Tap it and the panel asks the server about the file, shows its name, size and expiry, warns you when yours is the last download allowed, asks for the password if there is one, and downloads and decrypts it into **Downloads › WM Keyboard**. A picture can go straight into the chat field from there; anything else opens or shares from the panel.

You can also press **Receive a link instead** in the panel and paste the link into its box.

## Nearby

  {/* shot: tools/send-nearby */}
</PhoneFrame>

**Nearby** uses the same engine as the [KDE Connect](/tools/kde-connect/) tool, so it reaches phones and computers running WM Keyboard, KDE Connect, GSConnect or Valent on the same Wi-Fi. Pick files, pair with a device once by comparing the eight-character code, and press **Send** beside its name. Files sent to you land in **Downloads › WM Keyboard** and show in the panel's transfer list while they arrive.

### In a browser

The other device does not need WM Keyboard, or any app. Press **In a browser** and the phone starts a small web page on its Wi-Fi address, then shows a QR code. Whoever scans it on the same Wi-Fi gets a page in their browser with each file you picked and a **Download** button beside it. With **Accept files** on, the page also takes files back: choose or drop them there and they land in **Downloads › WM Keyboard** on your phone. Files you add or remove in the panel show up on the page within a few seconds.

When the other device is on a different network, or the Wi-Fi keeps its devices apart (common on guest and office networks), press **Use a hotspot**. The phone opens a Wi-Fi of its own, the same way the direct link below does, and the code sheet shows two codes: the first joins that Wi-Fi from a phone camera, the second opens the page. A laptop joins by typing the Wi-Fi name and password shown beside the code.

Nothing goes through the internet and no outside server is involved; the page comes straight from your phone. The address carries a random 128-bit token, so a device on the same Wi-Fi that did not get the code finds nothing. The page is plain HTTP, since browsers refuse a certificate a phone made for itself, so use it on networks you trust. It stops when you press **Stop** or after 10 minutes with nobody on it.

### With no Wi-Fi between you

Two phones with WM Keyboard can link directly. On the receiving phone press **Receive here**: the phone opens a Wi-Fi of its own (a Wi-Fi Direct group, or a local hotspot where the phone cannot do that) and shows a QR code. On the sending phone press **Scan a code** <Flavor edition="google" /> and point the camera at it. The code carries the Wi-Fi's name and password, the receiver's address and a one-time pairing token, so the sender joins the Wi-Fi, finds the receiver and pairs with it in one go; then the files go. **Disconnect** takes the Wi-Fi down again, unless **Keep a direct link up** is on.

Android asks for the **Nearby devices** permission before an app may open or join a Wi-Fi this way (on Android 12 and older, the same thing sits behind the location permission). The tool asks only when you press one of those two buttons, reads no position, and needs nothing at all for devices that are already on the same Wi-Fi.

## From other apps

With **Show in other apps' share sheets** on, **Send with WM Keyboard** appears beside the apps you share to. Share a file from anywhere, pick the limits and a password, and the link is copied for you, with its QR code on the card. Nearby works from there too, to a paired device in reach. A share that names a file inside WM Keyboard's own storage is ignored, so another app cannot use it to upload the keyboard's private files.

## Choosing a server

The panel's header chip names the instance uploads go to. Tap it for the list: the servers from the [community list](https://github.com/timvisee/send-instances) with their size, time and download limits, each with a dot that says whether it is answering, and **Add your own** for a server you run or trust. The default is the one the maintainer of Send runs. Every public instance is run by volunteers with no promises; what they see of your file is its size and its arrival time, nothing else.

If a file is too big for the chosen server, the panel says so and offers the instances with room for it.

## Settings

<SettingsPath path="Tools / Send files" />

Send files is the **Send files** bundle on [Extensions](/reference/settings/extensions/). Switch the bundle off and the tool, the link detection and the history screen leave together; the history stays on the phone.

| Setting | What it does |
|---|---|
| Instance | The server uploads go to, and the list of your own. |
| Link expires after | The default life of a new link: 5 minutes to 7 days, capped by the server. |
| Downloads allowed | The default download count of a new link. |
| Password | Off, ask on every upload, or generate one every time. |
| After the upload | Insert the link, copy it, show it, or ask. |
| Offer to receive links | The strip chip for a Send link typed, pasted or copied. |
| Open after download | A single received file opens as soon as it is saved. |
| Send to devices nearby | The Nearby mode, including the direct link and the browser page. |
| Keep a direct link up | Stay on the other phone's Wi-Fi after a transfer. |
| Show in other apps' share sheets | The **Send with WM Keyboard** entry. |
| Keep a history | The links you made and the files you received, for the History sheet and screen. |

Data saving has a row for this tool: a whole file over mobile data asks first, like a download.

## Privacy

The link is the key. The server you upload to receives only ciphertext; the server a link points at learns that you fetched it, which is unavoidable, and nothing about you beyond your address. Links you made are kept on the phone, with the owner token that can delete them, in a folder that is left out of every backup. Nothing about any of this goes to the developer. The network activity log lists every request the tool makes under **Send files**.
