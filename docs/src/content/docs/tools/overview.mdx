WM Keyboard ships 90 tools (panels, sensors, generators, and one-tap actions), but only a handful sit on the toolbar at once. The rest wait one tap away in the toolbox, and you decide which is which by dragging tools between the two.

## Pinning and reordering

The toolbar is a strip of pinned tools. The toolbox, behind the grid button on the toolbar, holds every other enabled tool that isn't pinned, and a tool never sits in both places at once. Out of the box a phone pins three: **Emoji**, **Clipboard**, and **Settings**. A tablet starts wider, with five on a small tablet (GIF and Voice join the three) and seven on a large one (Translate and Text edit as well); see [Size & position](/typing/size-position/#on-a-tablet). Everything else starts in the toolbox, ranked roughly by how often people reach for it: expressive media first, then everyday text helpers, then keyboard tweaks, with the specialty and sensor tools last.

Open the toolbox and hold-and-drag a tool:

- Drag a toolbox tool up onto the toolbar to pin it.
- Drag a tool around inside the toolbox grid to reorder it there.
- Drag a pinned toolbar tool back down into the toolbox to unpin it.
- Drop a tool on the middle of another tool to put the two in a folder. See [Folders](#folders). The middle is small on purpose: anywhere else on it, the tool takes that place. With a folder open, the star makes its toolbar button run the first tool on a tap and open the folder on a hold.

It's the same drag-to-pin model Gboard uses. The first time you open the toolbox, a hint explains the drag. Dismiss it and it only resurfaces occasionally as a reminder.

Picking **Recommended** rather than **Everything** during onboarding only decides which tools are *enabled*, meaning visible anywhere at all. It leaves the pinned row alone. The row stays at whatever your device shipped with until you drag something onto it yourself. If a tool you expected isn't in the toolbox, open <SettingsPath path="Tools" /> and turn it back on.

A keyboard [mode](/typing/modes/) can carry its own pinned toolbar, separate from this global one. Switching into that mode swaps the whole row. The modes page covers how that works.

## Hold a tool for a second action

<SettingsPath path="Tools / (any tool) / Press and hold on the toolbar" />

A pinned tool answers three gestures: a tap runs it, a hold that stays put does a second thing, and a hold that drags picks it up. The hold runs when you lift your finger, and only the hold: the tap's action does not run as well.

Out of the box, the tools that come in pairs hold to their partner, the same pairs HeliBoard uses:

| Tool | Hold runs |
|---|---|
| Clipboard | Paste |
| Paste | Clipboard |
| Copy | Cut |
| Undo | Redo |
| Redo | Undo |
| Select word | Select all |
| Select all | Select word |

Every other tool holds to its own settings page. The cursor tools have pairs too (left and right to a word left and right, up and down to page up and down, word left and right to the start and end of the line), but their hold repeats the move, so the pairs only take over once **Hold to repeat on the toolbar** is off; see [Text editing](/tools/text-editing/).

All of it is yours to change. Open any tool's own page and the **Press and hold on the toolbar** row picks another tool for its hold to run: hold Text edit to open the clipboard, say. The row shows what a hold does right now. The picker's first row, **Default**, says what the tool does untouched. **Settings page** gets the settings page back on a tool that has a pair, and **Does nothing** is for a tool whose hold you would rather have do nothing at all: it still buzzes, and nothing opens.

The picker fills the screen. The tools sit in the same groups as on the Tools page, with a search field over them that matches a tool's name or its description. Tap a group's heading to fold it away; a folded heading still shows how many tools it holds. The key and swipe action picker in the layout editor works the same way. Each picker opens again with the groups folded and scrolled the way you left them, until the app is closed. The first time, it opens on the current choice.

How long a press has to last before it counts as a hold is **Press and hold delay**, under <SettingsPath path="Appearance / Toolbar" />. At **System** it follows the touch and hold delay in your phone's accessibility settings; slide it up to 1.5 seconds if holds keep firing when you meant to tap, or down to 100 ms for a quicker hold. It applies to every hold on a tool, in the toolbox as well as on the bar.

The third gesture is optional too. **Rearrange by dragging**, under <SettingsPath path="Appearance / Toolbar" />, is on by default; switched off, a hold that drifts stays a hold and ends as whatever a stationary one would, and the toolbox is where you rearrange the bar instead.

- It changes the toolbar only. In the toolbox a hold always opens the tool's settings, and the Tools screen still lists every tool, so the settings page never goes out of reach.
- The bound tool runs whether or not it is on the toolbar or even enabled. Binding it is reason enough.
- The row is on every tool's page, pinned or not, so you can set a hold before you pin the tool. It does nothing until the tool is on the bar.
- Cursor tools that repeat on hold, Selection mode while its hold arms the mode, Trackpad while its hold opens the pad, and Voice while its hold picks a [voice typing mode](/tools/voice/#starting-dictation), say so instead of offering a second action. One gesture cannot do both. See **Repeat cursor tools on hold** under [Typing](/reference/settings/typing/).
- Binding a tool to itself is refused, since that is a slow tap.
- Nothing is shown while you hold. The buzz says the hold registered; the tool washes out and the drag notice appears only once your finger moves.

## Tools on the home screen

<SettingsPath path="Tools / (any tool) / Add to home screen" />

A tool with a panel can have an icon of its own on your home screen, so the level, the compass or the unit converter can stand in for an app you no longer need. **Add to home screen** on the tool's page asks your launcher to pin it. Tapping the icon opens a blank text box with the keyboard up and that tool already open on it. Whatever the tool types, such as a sum, a translation or a password, lands in the box, and **Copy** and **Share** under it take it from there. A second tool's icon opens in the same screen over a fresh box. The tool opens in WM Keyboard only, so if another keyboard is in use the screen says so and offers to switch. The Clock, Notes and To-do list pin their own screens in the app instead.

## What does this button do?

Inside a tool's panel, most buttons are bare icons: the clipboard's filter and list switch, a refresh arrow, a swap, the speaker in the dictionary. Press and hold any of them and its name pops up above it for a moment. A hold that shows the name doesn't press the button, so it's safe to ask before you tap. Buttons that already have a hold of their own keep it, and a button with its name written on it doesn't need one.

## Two ways to draw the toolbox

<SettingsPath path="Appearance / Toolbar" />

**Toolbox layout** picks between them:

- **Icons** (the default) is the grid you've seen above: a round icon per tool with its name in small text underneath, 4 to a row. Compact, and the most tools on screen at once.
- **Pills** gives each tool a wide rounded row instead, two to a row. The icon sits on the left in the tool's own color and the name reads across the middle at full size. Tools that *open* something get a small arrow on the right, and the arrow is the reason to use this layout. **Appearance** and **Clipboard** take you somewhere. **Flashlight** and **Undo** just do their thing and leave the keys where they are. The arrow tells you which is which before you tap.

Two settings apply to pills only. **Pills per row** goes from 1 to 3: one gives every name the full width, and three really only fits in landscape. **Fill pills with the tool color** paints the whole pill in the tool's accent color and flips the icon and name to white, or to near-black where the accent is too pale for white to read on. It needs **Colorful tool icons** (under <SettingsPath path="Tools" />) on, since that's where the colors come from.

Either layout still drags the same way: hold a tool to pick it up, drop it on the toolbar to pin it or elsewhere in the grid to reorder. The tool that follows your finger is drawn in the shape it will land in, and changes between them as you move: a full-width pill with its name over a pill toolbox, narrowing into the toolbar's circle as you carry it up to the bar, and widening again on the way back down. The grid closes up behind it as you go, and the drop keeps whatever arrangement you were looking at. The tool stays where you let go of it rather than flicking home and back.

## Most used or recently used first

The grid follows the order you drag it into until you change **Toolbox order** under <SettingsPath path="Appearance / Toolbox" />. **Most used** puts the tools you open most often first; **Recently used** puts the one you opened last first; **A to Z** sorts them by name, in the keyboard's language. Every way of running a tool counts: a tap on the toolbar or in the toolbox, a search, a key bound to the tool, a hardware shortcut. Tools you have never opened come after the rest, in your own order, so a fresh install looks the same either way.

The grid sorts itself each time the toolbox opens and holds still while it is open. Tap Flashlight in the toolbox and it stays where it was until the next time you open it. A folder sits where its first tool falls, and the tools inside it keep the folder's own order. Dragging still works, but while the grid is sorted by use a drop rearranges your own order rather than the grid you see; **Your order** brings that arrangement back.

The search has its own **Search order before typing** on the same screen. It decides how the search lists every tool before you type anything, so set it to **Recently used** and the tool you want is often waiting at the top. Once you type, the names that start with what you typed come first, as before.

## Scrolling or pages

By default the toolbox is one grid that scrolls up and down. Turn on **Swipe the toolbox in pages** and it splits into fixed pages you swipe sideways instead, with dots underneath showing where you are. **Tools per page** sets how many each one holds (12 by default, anywhere from 4 to 40). To move a tool onto another page, drag it to the left or right edge of the toolbox and hold it there for a moment: the page turns under your finger, and you can keep going or drop it there.

The trade is muscle memory against reach. Paging keeps every tool at the same spot on the same page every time, so you learn where things are instead of hunting for them mid-scroll. Scrolling gets you to the far end faster. Paging works with both layouts.

Pick a page size that's a multiple of your row size and every page comes out with full rows. Ask for more tools than fit the panel's height and the page will scroll as well as swipe, which rather defeats the point.

## Folders

A long toolbox is easier to scan in groups. Hold a tool, drag it over the middle of another one, and let go when that tool lights up: the two become a folder in that tool's place. The edges of a tool still mean "put it beside this one", so reordering works as before; only the middle files it. Drop more tools on the folder to add them, and drop a toolbar tool there to unpin it straight into the folder.

A new folder is called **Folder**. Tap it to open it in the toolbox, and the header shows what you can do with it:

- Tap the name to rename it. The keys come back under a shorter toolbox, the way they do for the other search boxes on the keyboard, and Enter or the check button keeps the name. Dictionary and Grammar might become "Language", for example.
- Drag the tools inside to change their order in the folder.
- Drag a tool onto the header to take it out of the folder. The header turns into a drop target while you drag.
- The pin button puts the folder on the toolbar, after your pinned tools. A tap on it there opens the toolbox at that folder. Tap the pin again to take it off. You can also drag the whole folder up onto the toolbar to pin it.
- The ungroup button breaks the folder up, and its tools go back to cells of their own.

The toolbox animates all of this. A folder opens by growing out of its cell and settles back into that spot when you leave it. A tool held over another makes that one swell to meet it, and the tool in your hand shrinks a little as if about to drop in. A new folder pops into place, and one that takes a tool gives a small bounce. **Reduce motion** under <SettingsPath path="Accessibility" /> turns every one of these off.

Hold a folder and drag it to move the whole folder around the grid. Back, the arrow in the header, or the system back gesture leaves the folder before it closes the toolbox. A folder left with a single tool is no longer a folder, and that last tool goes back to a cell of its own. Folders are saved with your settings, so a backup and restore brings them back. One set of folders is shared by every [keyboard mode](/typing/modes/); a mode with its own tool order just moves each folder to where its first tool falls.

## Searching the toolbox

While the toolbox is open, the toolbar shows a magnifier at its far end, after your pinned tools. Tap it and the search takes over the whole keyboard, the toolbar included, with a back button of its own at the left of the search box. The keys come back underneath, and you type the name with the keyboard itself. Every tool that matches is listed, including the ones inside folders, with names that start with what you typed first. Tap one to use it, or press Enter to open the first match. Results fade in one after another, and slide to their new places as you keep typing. Close the search with its back button, its X button or the system back gesture, and the toolbox is the way you left it. To take the magnifier off the toolbar, turn off **Toolbox search** under <SettingsPath path="Appearance / Toolbox" />. To have it next to the back button instead, turn off **Search button at the far end** on the same screen.

## Browsing every tool

<SettingsPath path="Tools" />

All 91 tools have a settings screen under `Settings → Tools`, each with its own **Enabled** switch plus whatever options it carries.

**Colorful tool icons** sits at the top of that screen and is on by default. It tints each tool's icon with the tool's own accent color, in the toolbox grid and down this settings list. The pinned row on the keyboard itself is the exception: those icons take the theme's toolbar-icon color, so the bar stays one color whatever this is set to, unless you turn on **Color the pinned tools** under [Toolbar](/reference/settings/appearance/). Turn the setting off and the toolbox falls back to that same plain foreground color.

Below that, the list is grouped by what the tools do: **Panels**, **Scanners**, **Online tools**, **Create and convert**, **Keyboard modes**, **Cursor**, **Quick actions**, and **Utilities**. Any tool a future group forgets to claim lands in an **Other** catch-all, so nothing goes invisible.

A row's switch enables or disables the tool everywhere at once: toolbar, toolbox, and hardware leader key. Tapping the row itself opens that tool's own settings.

To keep a tool working but out of the toolbox grid, open its page and turn off **Show in toolbox**. It still runs from the toolbar if pinned, from its keyword, from [selection actions](/smart/selection-actions/) and from the hardware leader key; the grid just loses one cell. Each tool has its own switch. A small tune icon marks the tools with settings beyond the switch. Most have them. Four don't, because their real options live on other screens: Settings, Sound & haptics, One-handed, and [Resize](/tools/resize/).

Related pages cover most of these tools in depth: [Clipboard manager](/tools/clipboard/), [Snippets & text expansion](/tools/snippets/), [Notes](/tools/notes/), [To-do list](/tools/todo/), [Text editing & cursor tools](/tools/text-editing/), [Trackpad](/tools/trackpad/), [Handwriting](/tools/handwriting/), [Camera tool](/tools/camera/), [Gallery](/tools/gallery/), [Send files](/tools/send/), [Voice typing](/tools/voice/), [Offline voice (Whisper)](/tools/whisper/), [Scanner (OCR, QR, documents)](/tools/scanner/), [Translate](/tools/translate/), [Search & Wikipedia](/tools/search/), [AI tools](/tools/ai/), [AI reply](/tools/ai-reply/), [Utility tools](/tools/utilities/), [Internet speed test](/tools/speed-test/), [Media controls](/tools/media/), [Music ID](/tools/music-id/), [Calendar](/tools/calendar/), [App launcher](/tools/app-launcher/), [Resize](/tools/resize/), and [Instruments](/tools/instruments/) (flashlight, compass, level, moon phase, weather). The master tool list is being built out on [Reference → Tools](/reference/settings/tools/).

## Panels and captured keys

Most tools that need input open a panel that captures the keyboard: search boxes, the AI prompt, the typing-test scorer, a plugin's own text field. While that panel is focused, what you type goes into its box rather than into the app behind it. Backspace is where this matters most. Word-deleting the field behind an open panel would edit text you can't currently see, so the keyboard routes deletes into the panel for as long as it's open. Space and <KeyCap>Enter</KeyCap> stay in the box too: Enter runs the box's own action (search, next match, keep this spelling) rather than dropping a newline into the app behind the panel.

### A captured box is a real text field

Those boxes type like the app's own field, not like a one-way buffer:

- **A caret you can move.** Tap anywhere in the text to put the caret there, and the next letter, backspace or swipe lands at that spot rather than at the end. The spacebar scrub, a hardware keyboard's arrows, <KeyCap>Home</KeyCap> and <KeyCap>End</KeyCap>, and a layout's own arrow keys all move it, and <KeyCap>Del</KeyCap> deletes forward from it. A delete swipe on <KeyCap>⌫</KeyCap> works there as it does in an app's field: it highlights what letting go will delete, by letter or by word, and dragging back gives it back. Long text scrolls to follow the caret instead of trailing off behind an ellipsis.
- **Selection.** Long-press a word to select it. A handle at each end drags the selection wider or narrower, and a bar over it offers **Cut**, **Copy**, **Paste** and **Select all**. Long-press where there is no word, or anywhere in an empty box, and the caret moves there with a **Paste** bar over it (plus **Select all** once there is text); a tap anywhere else puts it away. The toolbar's **Paste** tool and a layout's Paste key paste into the box too, at the caret, for as long as it has the keys. Typing, a swipe, a suggestion or backspace replaces the selected text, as in any field, and a tap puts the caret back. Shift with a hardware keyboard's arrows selects too. The handles and the bar are drawn inside the keyboard, never as a window of their own over the app.
- **Glide typing.** Swipe a word into a search box the same way you swipe one into a message. Each swipe adds a word, spaced off the word or the mark before it (`hello,` then a swipe gives `hello, world`, while an opening bracket keeps the word against it); the last word of a query just waits for its space until the next swipe, so the results are never held back a word. A chained swipe through the spacebar lands one word per leg, exactly as it does in a field. The two numeric boxes, the calculator's expression and the converters' amount, are the exception: there is no word list to decode a stroke against on a keypad.
- **Punctuation spacing.** With **Automatic space after punctuation** on, a mark typed into a box you write sentences in (the AI prompt, chat and reply box, a note's body, the clipboard's edit box, a caption, the calendar's notes, Home Assistant's Assist) is followed by a space, as in a message. A space pressed straight afterwards doesn't double it, and a second mark takes it back, so `?!` and `.)` stay together. Search boxes get no space after a mark: it would hold the results back a word.
- **Voice.** A mic at the right end of the box's suggestion strip dictates into the box, at the caret. See [Dictating into the keyboard's own boxes](/tools/voice/#dictating-into-the-keyboards-own-boxes).
- **Suggestions.** The box gets the suggestion strip in the row directly above the keys, with the same slots, the same size and the same words the field's own strip would offer. Tapping one replaces the word at the caret. The panel gives up that row rather than the keyboard growing one, so opening a search box doesn't move the keys under your thumbs. The emoji panel's search box is the one that reads differently: it's searching the emoji catalogue rather than writing prose, so its strip offers terms that catalogue can answer. See [Searching for an emoji](/emoji/picker/#searching-for-an-emoji).
- **Undo.** Once you've changed the text in one of these boxes, an undo arrow appears at the right end of its suggestion strip, before the mic. Each press takes back one step: a burst of typing counts as one step, and a paste, a picked suggestion or a cut is a step of its own. The strip and its arrow show while suggestions are on. It covers the note editor, the clipboard's edit box, the AI prompt and chat, find and replace, and every search box. The arrow goes away once there's nothing left to undo, and a box that opens on new text starts with no history. After an undo, a redo arrow appears beside it and puts the step back; typing anything new drops what was undone. A swipe or key bound to **Undo** or **Redo** acts on the box the same way.

### Typing in the app with a tool open

The box that has the keys carries a small switch at its right end, the same round button on every tool with a box of its own: the clipboard's search and edit box, Combine, find and replace, notes, the dictionary, the calculator and converters, translate, the AI prompt and chat, a plugin's text field, and the rest. Tap it and the keys go to the app's field behind the keyboard instead, with the tool still open. The button fills in, and the box fades and loses its caret, so you can see at a glance which field is taking the keys. Search the clipboard, then fix the address bar under it without closing the search.

Everything a key can do follows the switch together: letters, swipes, Backspace and forward delete, Space, <KeyCap>Enter</KeyCap>, the arrow keys and cursor tools, **Undo** and **Redo**, **Paste**, **Copy**, **Cut** and **Select all**, and a hardware keyboard. No action splits off to the other field. The calculator and the converters fold down over the key rows while the switch is on, since their own keypads only type into them.

Tap the switch again, or tap the box itself, and the box takes the keys back with its caret where you left it. Moving to another box in the same tool, or opening another tool, starts that box with the keys. The typing test and the toolbox search have no switch: their boxes are the whole point of the screen.

### Putting the keys down

The keys that come up under a tool's box cover most of the tool: the translation under Translate's box, the clips a search found, the rest of a note. To see it all again, put the keys down. The box keeps its text and its caret, and the tool takes back the room the keys had, so the keyboard stays the same height. Any of these does it:

- The keyboard button at the right end of the box's suggestion strip, after the undo arrow and the mic.
- The system Back button or gesture, with **Back puts a tool's keys down first** on (Appearance / Toolbox, off by default). The first Back then puts the keys down and the next one closes the tool. Off, Back closes the tool at once. The AI chat's message box and a plugin's text field always put the keys away on Back.
- A swipe down on the spacebar, with [**Swipe down to hide the keyboard**](/typing/gestures/) on, and the **Hide keyboard** tool or key. With a tool's keys up, these put down only the keys and leave the tool open.

Tap the box and the keys come back, with the caret where you tapped. Moving to another box, or opening another tool, brings the keys up for that box. A hardware keyboard still types into the box while the keys are down. The typing test and the toolbox's own boxes have no way to put the keys down: their keys are the point of the screen, and Back closes them.

On a short screen, a phone turned sideways most of all, the panel is what gives way. A captured box with the keys back underneath, or a tool that grows above the keyboard for more room (the AI reply panel, an AI chat, or any tool you have dragged taller), keeps the keyboard to at most 80% of the screen's height, and the panel shrinks to fit rather than squashing the keys. If the screen still can't hold both, the panel is measured against what's left once the keys are paid for, so the keys under a captured box always keep their full height. It never shrinks below its own header, so the box and the back arrow always stay in reach.

### Making a tool taller

A tool that takes the keyboard's place (AI, AI reply, translate, the converters, the dictionary and the rest) has the same short bar across its top edge. The calculator, both converters and the calendar all open at the keyboard's own height, so switching between them doesn't move the app above; their keypads and the month grid shrink to fit instead. Drag it up for a taller tool, down to go back to the height it opens at. Where you let go is kept, and it's one height for every such tool. The clipboard and the GIF and sticker panels keep their own bars and heights, described on their pages. With no room to grow, the bar isn't drawn.

### Making a panel over the keys taller

A panel that shrinks so the keys fit under it has a short bar across its top edge: the clipboard while it's [stacked over the keys](/tools/clipboard/#clipboard-and-keys-together) or searched, a [snippet search](/tools/snippets/#opening-the-panel), the dictionary's, the GIF and sticker searches, the web search, a note being written and the rest. Drag the bar up and the panel grows over the app, so more results fit above the keys; the keys stay where they are. Drag it down to go back to the panel's own compact height. Where you let go is kept, and it's one height for every such panel, so the keys sit at the same place whichever one is up. The same 80% ceiling applies, and with no room to grow the bar isn't drawn. The height is also a slider, **Height over the keys**, under <SettingsPath path="Clipboard" />. With TalkBack on, the bar offers **Make the panel taller** and **Make the panel shorter** as actions.

Nothing typed into a captured box is learned. A search query isn't writing, so it never reaches your personal dictionary, your word pairs or your typing stats.

Sensor and generator tools work differently. Compass, Level, Moon phase, Weather, Calendar, Password generator, Media controls, Camera, and the scanners all replace the key rows outright instead of intercepting keystrokes. There's no letter row to type on while they're open, so there's nothing to intercept.

Calculator, Unit converter and Currency converter fall between the two. Each draws its own keypad where the key rows were, and each also takes a physical keyboard's keystrokes into its own display: digits and operators build the expression or the amount, backspace trims it, and Enter runs `=` in the calculator instead of reaching the field behind. Handwriting is the other in-between case. While ink is waiting to be recognized, backspace throws that ink away rather than deleting text you already committed.

To back out of any open panel:

- Tap the back arrow that replaces the toolbox button while a panel is open.
- Press the system **Back** button or gesture, which closes the panel instead of dismissing the keyboard.
- On a hardware keyboard, press <KeyCap>Esc</KeyCap>, if [Esc closes the tool](#hardware-shortcuts-and-the-leader-key) is on (it is by default).

## Which tools work before you unlock your phone

**Direct boot** is the window right after a restart, before you've entered your PIN or pattern for the first time. The keyboard can't reach its stored data yet. Some tools work anyway.

WM Keyboard exposes 50 of its 90 tools during that window: everything that's pure arithmetic, a sensor reading, or a control over the keyboard's own on-screen state. That's Emoji, Text editing, Trackpad, Numpad, Symbols, One-handed, Split, Floating, Keep on screen, Resize, Hide keyboard, Appearance, Autocorrect, Sound & haptics, Incognito, Selection actions, English words, Find & replace, Text repeat, Modes, Fancy text, Secondary layout, Language, Undo, Redo, Power saving, Calculator, Unit converter, Password generator, QR generator, Flashlight, Compass, Level, Moon phase, Copy, Cut, and all fourteen cursor tools. Paste is the one clipboard button left out: the clipboard itself is credential-encrypted, so before the first unlock the button would be there and do nothing.

The other 40 sit it out until you unlock. That covers anything backed by a file on disk (Clipboard, Snippets, Notes, To-do list, Camera, Read back, downloaded speech or AI models), anything that needs a credential or the network (Translate, the online searches, AI, the paired computers of KDE Connect, the signed-in homes of the Smart home tool, Send files), anything that reads a content provider behind the lock screen (Calendar), and anything that has to launch a separate activity (Settings, Statistics, the document scanner). None of it is a toggle. The split is automatic, and it only applies before that first unlock.

**Hide toolbar & clipboard on lock screen** under <SettingsPath path="Appearance / Toolbar" /> is a different thing, and it's off by default. It hides the *entire* toolbar rather than filtering it, any time the screen is locked, including long after you've unlocked the phone once since the last restart. Turn it on if you'd rather not have a pinned tool or the suggestion strip visible while you reply to a notification from the lock screen. Everything comes back the moment you unlock, even in the text box the keyboard was open in when the screen turned off, and even when a fingerprint unlocks the phone straight from a dark screen.

## Hardware shortcuts and the leader key

<SettingsPath path="Typing / Physical keyboard" />

With a physical keyboard attached, double-tap <KeyCap>Ctrl</KeyCap>, the default leader. Then press a letter to jump straight to a tool without touching the screen. About two dozen tools have a default letter: Emoji is <KeyCap>E</KeyCap>, Clipboard is <KeyCap>C</KeyCap>, Voice is <KeyCap>V</KeyCap>. Press <KeyCap>T</KeyCap> after the leader to open the full toolbox instead, or <KeyCap>?</KeyCap> to expand the on-screen hint into a two-column legend of every binding. [Hardware keyboards](/typing/hardware-keyboard/) has the full mechanics, plus how to rebind the leader and every letter.

The leader is one switch in a broader hardware-keyboard group. Arrow-key navigation inside an open panel and whether <KeyCap>Esc</KeyCap> closes a panel are separate switches in the same place, each on by default.

## Options

<SettingsPath path="Appearance / Toolbar" />

- **Show the toolbar**: on by default. Turning it off reclaims its height for the keys, but also hides suggestions and every pinned tool, so Settings warns you before you do it.
- **Swipe down to hide**: off by default. A downward flick anywhere on the toolbar dismisses the keyboard.
- **Only toolbar with hardware keyboard**: off by default. With a physical keyboard attached, drop the on-screen keys and keep just the toolbar strip.
- **Reverse order for RTL languages**: off by default. Mirrors the pinned tool order when the active layout's script runs right-to-left.
- **Tool layout**: Spread out by default. Fixed size packs the pinned tools to the left at one size, Spread out splits the width evenly, and Scroll keeps each tool at a comfortable size and lets the bar scroll sideways.
- **Hide toolbar & clipboard on lock screen**: off by default. See [above](#which-tools-work-before-you-unlock-your-phone).
- **Toolbar top padding** and **Toolbar bottom padding**: 4dp and 0dp by default, each adjustable from 0–24dp. They add space above and below the tools, and the keyboard grows by the same amount.
- **Tool labels**: off by default. Shows each tool's name under its icon. The label is 10sp by default.
- **Reset pinned tools**: restores the toolbar to Emoji, Clipboard, and Settings, after a confirmation. This always resets the *global* row, even while a mode with its own pinned toolbar is active. To change what a mode itself pins, edit that mode instead. On a tablet, reset writes the shipped three and the tablet's own default immediately re-expands it, so you get five or seven back rather than three. It touches the pinned row alone; the grid has its own row below.
- **Reset toolbox order**: puts the toolbox grid back in the order it shipped in, after a confirmation. Only shown once you've dragged something. See [below](#details--edge-cases).
- **Tool circle radius**: 20dp by default (a full circle behind each icon, Gboard-style). Lower values give a rounded square, and 0 removes the background entirely.
- **Tool background shape**: Rounded by default. The outline of that background, from the same set of shapes the keys and popups use. Only shown while the radius above is over 0, since at 0 there's no background to shape.
- **Tool background width**: 38dp by default, adjustable from 38–64dp. 38 is the classic circle. Wider stretches it into a pill, which pairs well with a low corner radius and a scrolling bar.
- **Toolbox layout**: Icons by default. Pills is the wide-row alternative, see [above](#two-ways-to-draw-the-toolbox).
- **Toolbox grid size**: 4 tools per row by default, adjustable from 3–6. Icons layout only.
- **Pills per row**: 2 by default, adjustable from 1–3. Pills layout only.
- **Fill pills with the tool color**: off by default. Pills layout only, and needs Colorful tool icons on.
- **Toolbox order**: Your order by default. A to Z sorts by name. Most used and Recently used rank the grid by use; see [above](#most-used-or-recently-used-first).
- **Search order before typing**: Your order by default. The same three choices, for the search's list before you type.
- **Swipe the toolbox in pages**: off by default. See [above](#scrolling-or-pages).
- **Tools per page**: 12 by default, adjustable from 4–40. Only shown once paging is on.

## Details & edge cases

- A tool that's disabled under <SettingsPath path="Tools" /> disappears from the toolbar, the toolbox, *and* its hardware leader-key letter all at once, since there's a single switch, not three.
- Every tool is in the F-Droid build, though three read with open-source stand-ins for the Google libraries it leaves out. QR scan reads with zxing-cpp. Text scan reads with PaddleOCR on MNN, which covers Chinese, Japanese and Latin script. Handwriting reads Chinese and Japanese with zinnia and nine other scripts with PaddleOCR's text recognisers on MNN; languages in other scripts, Bangla among them, have none. Grammar needs Harper's, which F-Droid compiles from source, so it stays. A build-gated tool gets no settings row at all, so you never meet a switch that won't turn on.
- **Document scanner** is in every build and on every phone. It opens Google's scanner, an activity inside Google Play services, where that can run, and the keyboard's own [built-in scanner](/tools/scanner/#scanning-a-document) everywhere else, F-Droid's build included.
- **Reset toolbox order** puts the grid back in the order it shipped in, after a confirmation. It sits under <SettingsPath path="Appearance / Toolbar" /> right below Reset pinned tools, and only appears once you have actually dragged something. It leaves the pinned row and which tools are enabled alone. **Reset pinned tools** is the mirror of it.
- Toolbar reordering is per-installation, not per-language. Pinning a tool applies everywhere, not only while a particular language is active. A keyboard mode's own toolbar override is the one exception. See [above](#pinning-and-reordering).
- The toolbox shows only tools that are both enabled *and* not already pinned, so enabling a tool that's already pinned won't create a second entry in the toolbox.
- A tool pinned to the toolbar stays a member of its folder but isn't shown inside it. Unpin it and it is back in the folder. A folder whose tools are all pinned or hidden disappears from the grid until one of them comes back.
- The search lists results only. While it is open you can tap a result or hold it for its settings, but nothing can be dragged in a filtered grid.
- With paging on, a drag reorders within the page you're holding it over. The pages don't flip under your finger, so moving a tool to another page means dragging it onto the toolbar first, then off again on the page you want. Dragging up onto the toolbar to pin works from any page.
- The pill layout's arrow follows what the tool actually does, not what kind of tool it is. **Document scanner** gets one because it opens a full-screen scanner, and **Settings** gets one because it opens the settings app, even though neither is a keyboard panel.
- Tool icon colors apply in the toolbox and the settings list, and on the toolbar too with **Color the pinned tools** on, and only when **Colorful tool icons** is on. With it off, those icons use the theme's plain foreground color, whatever per-tool override you've set.
