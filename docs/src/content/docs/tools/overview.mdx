WM Keyboard ships 64 tools (panels, sensors, generators, and one-tap actions), but only a handful sit on the toolbar at once. The rest wait one tap away in the toolbox, and you decide which is which by dragging tools between the two.

## Pinning and reordering

The toolbar is a strip of **pinned** tools. The toolbox, behind the grid button on the toolbar, holds every other **enabled** tool that isn't pinned, and a tool never sits in both places at once. Out of the box a phone pins three: **Emoji**, **Clipboard**, and **Settings**. A tablet starts wider, with five on a small tablet (GIF and Voice join the three) and seven on a large one (Translate and Text edit as well); see [Size & position](/typing/size-position/#on-a-tablet). Everything else starts in the toolbox, ranked roughly by how often people reach for it: expressive media first, then everyday text helpers, then keyboard tweaks, with the specialty and sensor tools last.

Open the toolbox and hold-and-drag a tool:

- Drag a toolbox tool up onto the toolbar to pin it.
- Drag a tool around inside the toolbox grid to reorder it there.
- Drag a pinned toolbar tool back down into the toolbox to unpin it.

It's the same drag-to-pin model Gboard uses. The first time you open the toolbox, a hint explains the drag. Dismiss it and it only resurfaces occasionally as a reminder.

Picking **Recommended** rather than **Everything** during onboarding only decides which tools are *enabled*, meaning visible anywhere at all. It leaves the pinned row alone. The row stays at whatever your device shipped with until you drag something onto it yourself. If a tool you expected isn't in the toolbox, open <SettingsPath path="Tools" /> and turn it back on.

A keyboard [mode](/typing/modes/) can carry its own pinned toolbar, separate from this global one. Switching into that mode swaps the whole row. The modes page covers how that works.

## Hold a tool for a second action

<SettingsPath path="Tools / (any tool) / Press and hold on the toolbar" />

A pinned tool answers three gestures: a tap runs it, a hold that stays put opens its settings page, and a hold that drags picks it up. The middle one is yours to rebind. Open any tool's own page and the **Press and hold on the toolbar** row picks another tool for its hold to run: hold Undo to redo, hold Text edit to open the clipboard. The row shows what a hold does right now, and **Opens this tool's settings** means nothing is bound.

- It changes the toolbar only. In the toolbox a hold always opens the tool's settings, and the Tools screen still lists every tool, so the settings page never goes out of reach.
- The bound tool runs whether or not it is on the toolbar or even enabled. Binding it is reason enough.
- The row is on every tool's page, pinned or not, so you can set a hold before you pin the tool. It does nothing until the tool is on the bar.
- Cursor tools that repeat on hold, and Selection mode while its hold arms the mode, say so instead of offering a second action. One gesture cannot do both. See **Repeat cursor tools on hold** under [Typing](/reference/settings/typing/).
- Binding a tool to itself is refused, since that is a slow tap.
- Nothing is shown while you hold. The buzz says the hold registered; the tool washes out and the drag notice appears only once your finger moves.

## Two ways to draw the toolbox

<SettingsPath path="Appearance / Toolbar" />

**Toolbox layout** picks between them:

- **Icons** (the default) is the grid you've seen above: a round icon per tool with its name in small text underneath, 4 to a row. Compact, and the most tools on screen at once.
- **Pills** gives each tool a wide rounded row instead, two to a row. The icon sits on the left in the tool's own color and the name reads across the middle at full size. Tools that *open* something get a small arrow on the right, and the arrow is the reason to use this layout. **Themes** and **Clipboard** take you somewhere. **Flashlight** and **Undo** just do their thing and leave the keys where they are. The arrow tells you which is which before you tap.

Two settings apply to pills only. **Pills per row** goes from 1 to 3: one gives every name the full width, and three really only fits in landscape. **Fill pills with the tool color** paints the whole pill in the tool's accent color and flips the icon and name to white, or to near-black where the accent is too pale for white to read on. It needs **Colorful tool icons** (under <SettingsPath path="Tools" />) on, since that's where the colors come from.

Either layout still drags the same way: hold a tool to pick it up, drop it on the toolbar to pin it or elsewhere in the grid to reorder.

## Scrolling or pages

By default the toolbox is one grid that scrolls up and down. Turn on **Swipe the toolbox in pages** and it splits into fixed pages you swipe sideways instead, with dots underneath showing where you are. **Tools per page** sets how many each one holds (12 by default, anywhere from 4 to 40).

The trade is muscle memory against reach. Paging keeps every tool at the same spot on the same page every time, so you learn where things are instead of hunting for them mid-scroll. Scrolling gets you to the far end faster. Paging works with both layouts.

Pick a page size that's a multiple of your row size and every page comes out with full rows. Ask for more tools than fit the panel's height and the page will scroll as well as swipe, which rather defeats the point.

## Browsing all 64 tools

<SettingsPath path="Tools" />

Every tool has a settings screen under `Settings → Tools`, with its own **Enabled** switch plus whatever options it carries.

**Colorful tool icons** sits at the top of that screen and is on by default. It tints each tool's icon with the tool's own accent color, in the toolbox grid and down this settings list. The pinned row on the keyboard itself is the exception: those icons always take the theme's toolbar-icon color, so the bar stays one color whatever this is set to. Turn the setting off and the toolbox falls back to that same plain foreground color.

Below that, the list is grouped by what the tools do: **Panels**, **Scanners**, **Online tools**, **Create and convert**, **Keyboard modes**, **Cursor**, **Quick actions**, and **Utilities**. Any tool a future group forgets to claim lands in an **Other** catch-all, so nothing goes invisible.

A row's switch enables or disables the tool everywhere at once: toolbar, toolbox, and hardware leader key. Tapping the row itself opens that tool's own settings. A small tune icon marks the tools with settings beyond the switch. Most have them. Six don't, because their real options live on other screens: Settings, Themes, Sound & haptics, One-handed, Media controls, and [Resize](/tools/resize/).

Related pages cover most of these tools in depth: [Clipboard manager](/tools/clipboard/), [Snippets & text expansion](/tools/snippets/), [Text editing & cursor tools](/tools/text-editing/), [Handwriting](/tools/handwriting/), [Camera tool](/tools/camera/), [Voice typing](/tools/voice/), [Offline voice (Whisper)](/tools/whisper/), [Scanner (OCR, QR, documents)](/tools/scanner/), [Translate](/tools/translate/), [Search & Wikipedia](/tools/search/), [AI tools](/tools/ai/), [Utility tools](/tools/utilities/), [Media controls](/tools/media/), [Calendar](/tools/calendar/), [App launcher](/tools/app-launcher/), [Resize](/tools/resize/), and [Instruments](/tools/instruments/) (flashlight, compass, level, moon phase, weather). The master tool list is being built out on [Reference → Tools](/reference/settings/tools/).

## Panels and captured keys

Most tools that need input open a panel that **captures the keyboard**: search boxes, the AI prompt, the typing-test scorer, a plugin's own text field. While that panel is focused, what you type goes into its box rather than into the app behind it. Backspace is where this matters most. Word-deleting the field behind an open panel would edit text you can't currently see, so the keyboard routes deletes into the panel for as long as it's open.

Sensor and generator tools work differently. Compass, Level, Moon phase, Weather, Calendar, Password generator, Media controls, Camera, and the scanners all replace the key rows outright instead of intercepting keystrokes. There's no letter row to type on while they're open, so there's nothing to intercept.

Calculator, Unit converter and Currency converter fall between the two. Each draws its own keypad where the key rows were, and each also takes a physical keyboard's keystrokes into its own display: digits and operators build the expression or the amount, backspace trims it, and Enter runs `=` in the calculator instead of reaching the field behind. Handwriting is the other in-between case. While ink is waiting to be recognized, backspace throws that ink away rather than deleting text you already committed.

To back out of any open panel:

- Tap the back arrow that replaces the toolbox button while a panel is open.
- Press the system **Back** button or gesture, which closes the panel instead of dismissing the keyboard.
- On a hardware keyboard, press <KeyCap>Esc</KeyCap>, if [Esc closes the tool](#hardware-shortcuts-and-the-leader-key) is on (it is by default).

## Which tools work before you unlock your phone

**Direct boot** is the window right after a restart, before you've entered your PIN or pattern for the first time. The keyboard can't reach its stored data yet. Some tools work anyway.

WM Keyboard exposes 39 of its 64 tools during that window: everything that's pure arithmetic, a sensor reading, or a control over the keyboard's own on-screen state. That's Emoji, Text editing, Numpad, Symbols, One-handed, Split, Floating, Resize, Hide keyboard, Themes, Autocorrect, Sound & haptics, Incognito, Modes, Fancy text, Undo, Redo, Power saving, Calculator, Unit converter, Password generator, QR generator, Flashlight, Compass, Level, Moon phase, and all thirteen cursor tools.

The other 25 sit it out until you unlock. That covers anything backed by a file on disk (Clipboard, Snippets, Camera, downloaded speech or AI models), anything that needs a credential (Translate, the online searches, AI), anything that reads a content provider behind the lock screen (Calendar), and anything that has to launch a separate activity (Settings, the document scanner). None of it is a toggle. The split is automatic, and it only applies before that first unlock.

**Hide toolbar & clipboard on lock screen** under <SettingsPath path="Appearance / Toolbar" /> is a different thing, and it's off by default. It hides the *entire* toolbar rather than filtering it, any time the screen is locked, including long after you've unlocked the phone once since the last restart. Turn it on if you'd rather not have a pinned tool or the suggestion strip visible while you reply to a notification from the lock screen.

## Hardware shortcuts and the leader key

<SettingsPath path="Typing / Physical keyboard" />

With a physical keyboard attached, double-tap <KeyCap>Ctrl</KeyCap>, the default leader. Then press a letter to jump straight to a tool without touching the screen. About two dozen tools have a default letter: Emoji is <KeyCap>E</KeyCap>, Clipboard is <KeyCap>C</KeyCap>, Voice is <KeyCap>V</KeyCap>. Press <KeyCap>T</KeyCap> after the leader to open the full toolbox instead, or <KeyCap>?</KeyCap> to expand the on-screen hint into a two-column legend of every binding. [Hardware keyboards](/typing/hardware-keyboard/) has the full mechanics, plus how to rebind the leader and every letter.

The leader is one switch in a broader hardware-keyboard group. Arrow-key navigation inside an open panel and whether <KeyCap>Esc</KeyCap> closes a panel are separate switches in the same place, each on by default.

## Options

<SettingsPath path="Appearance / Toolbar" />

- **Show the toolbar**: on by default. Turning it off reclaims its height for the keys, but also hides suggestions and every pinned tool, so Settings warns you before you do it.
- **Swipe down to hide**: off by default. A downward flick anywhere on the toolbar dismisses the keyboard.
- **Only toolbar with hardware keyboard**: off by default. With a physical keyboard attached, drop the on-screen keys and keep just the toolbar strip.
- **Reverse order for RTL languages**: on by default. Mirrors the pinned tool order when the active layout's script runs right-to-left.
- **Spread tools across the bar**: on by default. Pinned tools split the available width evenly instead of packing to the left.
- **Scroll the toolbar**: off by default. Lets pinned tools scroll sideways instead of shrinking to fit. Turning it on forces the packed (non-spread) layout.
- **Hide toolbar & clipboard on lock screen**: off by default. See [above](#which-tools-work-before-you-unlock-your-phone).
- **Toolbar height**: 44dp by default, adjustable from 32–80dp.
- **Tool labels**: off by default. Shows each tool's name under its icon. The label is 10sp by default.
- **Reset pinned tools**: restores the toolbar to Emoji, Clipboard, and Settings, after a confirmation. This always resets the *global* row, even while a mode with its own pinned toolbar is active. To change what a mode itself pins, edit that mode instead. On a tablet, reset writes the shipped three and the tablet's own default immediately re-expands it, so you get five or seven back rather than three. It touches the pinned row alone; the grid has its own row below.
- **Reset toolbox order**: puts the toolbox grid back in the order it shipped in, after a confirmation. Only shown once you've dragged something. See [below](#details--edge-cases).
- **Tool circle radius**: 20dp by default (a full circle behind each icon, Gboard-style). Lower values give a rounded square, and 0 removes the background entirely.
- **Tool background shape**: Rounded by default. The outline of that background, from the same set of shapes the keys and popups use. Only shown while the radius above is over 0, since at 0 there's no background to shape.
- **Tool background width**: 38dp by default, adjustable from 38–64dp. 38 is the classic circle. Wider stretches it into a pill, which pairs well with a low corner radius and a scrolling bar.
- **Toolbox layout**: Icons by default. Pills is the wide-row alternative, see [above](#two-ways-to-draw-the-toolbox).
- **Toolbox grid size**: 4 tools per row by default, adjustable from 3–6. Icons layout only.
- **Pills per row**: 2 by default, adjustable from 1–3. Pills layout only.
- **Fill pills with the tool color**: off by default. Pills layout only, and needs Colorful tool icons on.
- **Swipe the toolbox in pages**: off by default. See [above](#scrolling-or-pages).
- **Tools per page**: 12 by default, adjustable from 4–40. Only shown once paging is on.

## Details & edge cases

- A tool that's disabled under <SettingsPath path="Tools" /> disappears from the toolbar, the toolbox, *and* its hardware leader-key letter all at once, since there's a single switch, not three.
- Five tools ship native libraries the Lite build leaves out, so they are <Flavor edition="full" />: Handwriting, OCR, QR scan, and Document scanner need ML Kit, and Grammar needs Harper's. Lite ships 59 tools instead of 64. A build-gated tool gets no settings row at all, so you never meet a switch that won't turn on.
- **Document scanner** has a second gate on top of that one: it's an activity inside Google Play services, not this app's own code, so it's hidden on any device without Play services even on <Flavor edition="full" />. OCR and QR scan stay put there, since their models ship in the APK and run with no Play services at all.
- **Reset toolbox order** puts the grid back in the order it shipped in, after a confirmation. It sits under <SettingsPath path="Appearance / Toolbar" /> right below Reset pinned tools, and only appears once you have actually dragged something. It leaves the pinned row and which tools are enabled alone. **Reset pinned tools** is the mirror of it.
- Toolbar reordering is per-installation, not per-language. Pinning a tool applies everywhere, not only while a particular language is active. A keyboard mode's own toolbar override is the one exception. See [above](#pinning-and-reordering).
- The toolbox shows only tools that are both enabled *and* not already pinned, so enabling a tool that's already pinned won't create a second entry in the toolbox.
- With paging on, a drag reorders within the page you're holding it over. The pages don't flip under your finger, so moving a tool to another page means dragging it onto the toolbar first, then off again on the page you want. Dragging up onto the toolbar to pin works from any page.
- The pill layout's arrow follows what the tool actually does, not what kind of tool it is. **Document scanner** gets one because it opens Google's full-screen scanner, and **Settings** gets one because it opens the settings app, even though neither is a keyboard panel.
- Tool icon colors only apply in the toolbox and the settings list, and only when **Colorful tool icons** is on. With it off, those icons use the theme's plain foreground color, whatever per-tool override you've set.
