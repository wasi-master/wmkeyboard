The **WM Pass** tool types logins from [WM Pass](https://github.com/wasi-master/wm-pass), a separate password manager from the same author. The keyboard does not hold your vault. It asks WM Pass for one value when you tap it, types it into the field, and keeps nothing.

## Setting it up

1. Install WM Pass and make a vault there.
2. In WM Pass, open **Settings**, then **Security**, and turn on **Let WM Keyboard fill**. It is off until you do this.
3. In WM Keyboard, add the **WM Pass** tool to your toolbar from the Tools list.

## Using it

Open the tool while the field you want is focused. Logins saved for the app in front come first, followed by the rest of the vault, because a browser does not tell a keyboard which site it is showing. Tap **Username**, **Password** or **Code** under a login to type that value.

If the vault is locked, the tool says so and offers **Open WM Pass**. You always unlock in WM Pass itself: the keyboard never sees your master password, and it cannot unlock anything.

## The code chip

With one-time code chips turned on, focusing a code box in an app that has a login saved in WM Pass offers its current code on the suggestion strip. It uses the same chip as codes read from notifications, and it disappears when the code stops being valid. Tap it to type the code.

## API keys in settings

The key fields in WM Keyboard's settings get a WM Pass button once WM Pass has a vault and **Let WM Keyboard fill** is on. They include the key and secret of every service under Providers (translation, AI, search, GIFs and the rest), smart home tokens, the Hugging Face and Telegram bot tokens, the GitHub token for imports, and a voice server's key. On a phone without WM Pass the fields look as they always did.

- **Fill from WM Pass** lists the API key items in your vault, with the ones named for that service first. Pick one and its key goes into the field.
- **Save in WM Pass** keeps what the field holds as an API key item named for the service, such as "DeepL", or "DeepL (Work)" for a second DeepL key you gave a name. If an item of that name is already there, WM Pass changes its key and keeps the old one in the item's history. A service that has a key and a secret ends up as one item that holds both.

If the vault is locked, the button opens WM Pass. Unlock it there, come back, and press the button again.

## What this means for privacy

A password you type this way passes through the keyboard's process on its way to the field, as anything you type does. It goes through the same path as a generated password, so it is not learned, predicted from or added to your typing statistics. Nothing is written to disk, and no network is involved.

Each side checks the other. WM Pass answers only a WM Keyboard signed by a known certificate, and WM Keyboard asks only a WM Pass signed by a known certificate. An app that copied the name gets nothing and is told nothing.

If you would rather keep passwords out of the keyboard's process altogether, leave this off and use WM Pass as your device's autofill service instead.
