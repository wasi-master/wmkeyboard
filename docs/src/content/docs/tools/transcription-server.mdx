The transcription server is another dictation engine, next to the system recognizer, [offline Whisper](/tools/whisper/), [offline Whistle](/tools/whistle/), [offline Asr4All](/tools/asr4all/), [offline Parakeet](/tools/parakeet/) and [offline Moonshine](/tools/moonshine/). The keyboard records what you say and sends the recording to a server you choose. The server sends back the text. The heavy work runs on a computer on your desk or in your rack, not on your phone's battery, and you choose the model.

It works in every build, F-Droid's included. The phone needs only a small library (about 300 KB) that compresses each recording to about a twelfth of its size before it is sent, fetched the first time you dictate with this engine. Until it is there, recordings go uncompressed, and dictation works the same. See [How much it sends](#how-much-it-sends).

## Setting it up

<SettingsPath path="Voice typing" />

1. Under **Recognition engine**, press **Add a provider** and pick **Transcription server**.
2. In the sheet that opens, fill in **Server address**. For a server on your own network it looks like `http://192.168.1.10:8000/v1`. An address has no spaces, so if the field turns red and says so, something was pasted along with the address, such as the line of a provider's docs that follows it. Remove everything after the address.
3. Fill in **Model** if your server needs one (see the recipes below). Fill in **API key** if it asks for one, and **Endpoint path** for a server on a route of its own.
4. Press **Test**. The keyboard sends one second of silence and says whether the server answered. If it fails, it shows the same message a failed dictation would show. Then press **Add**.
5. Drag the server to the top of the list to make it the engine for every language, or give it only some languages under **Engine for each language**.

You can add more than one server, each with its own address, key and model, and switch one off without losing it. Dictation sends to the first server on the list that is on.

Dictation then works the way it does with offline Whisper. Speak, then press the microphone when you are done (or let the 30-second clip fill, or set **Stop after a pause** under Voice typing and let a pause end it). The phrase lands a moment later, with [spoken punctuation](/tools/voice/), spacing and undo applied as usual. **Keep listening** chains the next phrase the same way.

Press a server's row to open its screen: **Setup** reopens the sheet, and **Send the keyboard language**, the prompt and the server languages are there too. **Send the keyboard language** is on by default. It tells the server the language of your active layout, which is faster and more accurate than letting it guess from a short clip. Turn it off if you dictate in two languages on one layout and want the server to detect which one you are speaking. With a [Voice typing language](/tools/voice/#language-and-engine) picked, the server is told that language instead, and with several picked it's told none and detects it.

## The address

Type the server's API root, up to and including the version segment, the same way the AI tool's [Other service](/tools/ai/#any-other-openai-compatible-service) asks for it. The keyboard adds `/audio/transcriptions` itself.

| You type | The keyboard sends to |
|---|---|
| `http://192.168.1.10:8000/v1` | `http://192.168.1.10:8000/v1/audio/transcriptions` |
| `http://192.168.1.10:8000` | `http://192.168.1.10:8000/v1/audio/transcriptions` (a bare address gets `/v1`) |
| `https://api.groq.com/openai/v1` | `https://api.groq.com/openai/v1/audio/transcriptions` |
| `http://192.168.1.10:8080/inference` | used as it is (whisper.cpp's own endpoint) |

An address that already ends in `/transcriptions` or `/inference` is used as typed.

### A server with its own route

Some servers take the same request on a route of their own, such as `POST /v1/transcribe`. Put that route in **Endpoint path**, under **Server address**. When it is filled in, the keyboard adds it to the address exactly as typed, with no guessing and no `/v1`:

| Server address | Endpoint path | The keyboard sends to |
|---|---|---|
| `http://192.168.1.10:8000` | `/v1/transcribe` | `http://192.168.1.10:8000/v1/transcribe` |
| `http://192.168.1.10:8000/v1` | `transcribe` | `http://192.168.1.10:8000/v1/transcribe` |
| `http://192.168.1.10:8000` | `https://asr.example.com/api/stt` | `https://asr.example.com/api/stt` (a whole address replaces the server address) |

Leave **Endpoint path** empty for the usual `/audio/transcriptions`. The request itself is the same either way; see [The protocol](#the-protocol).

## A model or server per language

Some models are much better at one language than another. With two or more languages enabled, a **Per language** group appears in the **Transcription server** group under the engine list, with one row per language. Each row says what that language uses. Tap it to change it:

- **Same server, another model.** Leave **Server address** empty and fill in **Model**. The language uses the main server (the first one on the list), its route and its key, with this model instead of the main one. Leave **Model** empty too and the language goes back to the main server.
- **A server of its own.** Fill in **Server address**. **Endpoint path** and **API key** appear for that server. Nothing is borrowed from the main server: the main key is never sent to a different address, and an empty **Model** lets this server pick its own.

**Test** in the dialog sends one second of silence to what the dialog holds, before you save. **Use main server** clears the language's entry.

Dictation picks the server from the language of the layout you are typing on, the same way [offline Whisper](/tools/whisper/) picks a model. **Send the keyboard language**, **Prompt** and the words to listen for apply to every server. A language's own API key is left out of backups unless you choose to include API keys, like the main one.

## Running a server

The keyboard does not use a protocol of its own. It speaks OpenAI's audio transcription API, which most speech-to-text servers already support. Any of these works.

### speaches (faster-whisper)

[speaches](https://github.com/speaches-ai/speaches) runs faster-whisper behind an OpenAI-compatible API. On a machine with Docker:

```bash
docker run --detach --publish 8000:8000 --name speaches \
  --volume hf-hub-cache:/home/ubuntu/.cache/huggingface/hub \
  ghcr.io/speaches-ai/speaches:latest-cpu
```

Use the `latest-cuda` image with `--gpus=all` on a machine with an NVIDIA GPU. speaches only runs models you have downloaded, so fetch one once:

```bash
curl -X POST http://localhost:8000/v1/models/Systran/faster-whisper-small
```

Then set:

- **Server address**: `http://<computer's address>:8000/v1`
- **Model**: the id you downloaded, here `Systran/faster-whisper-small`. For English only, `Systran/faster-distil-whisper-small.en` is faster.

### whisper.cpp

[whisper.cpp](https://github.com/ggml-org/whisper.cpp) ships `whisper-server`, a single binary with no Python. Download a model and start it on all interfaces:

```bash
whisper-server -m models/ggml-base.bin -l auto --host 0.0.0.0 --port 8080 \
  --inference-path /v1/audio/transcriptions
```

With `--inference-path` as above, set **Server address** to `http://<computer's address>:8080/v1`. Without it, point the keyboard at `http://<computer's address>:8080/inference`. Leave **Model** empty: whisper-server uses the model it was started with. `-l auto` matters when **Send the keyboard language** is off. Without it whisper-server assumes English.

whisper-server reads WAV, MP3 and FLAC on its own. Add `--convert` (it needs `ffmpeg` on the computer) and it also reads the keyboard's compressed recordings, which are a twelfth of the size. Without it, the first phrase tells the keyboard so, and that server gets WAV from then on. An address ending in `/inference` always gets WAV.

### Cloud services

The same engine reaches the hosted APIs, if you would rather pay per minute than run a machine:

| Service | Server address | Model |
|---|---|---|
| Groq | `https://api.groq.com/openai/v1` | `whisper-large-v3-turbo` |
| OpenAI | `https://api.openai.com/v1` | `whisper-1` or `gpt-4o-mini-transcribe` |

Both need an **API key**. LocalAI and other OpenAI-compatible gateways work too.

## The protocol

This is everything the keyboard sends and expects, so you can build or proxy a server of your own.

**Request.** `POST <endpoint>` with `Content-Type: multipart/form-data`, and these parts:

| Part | Sent | Contents |
|---|---|---|
| `file` | always | the clip, up to 30 seconds, as `speech.ogg`, `audio/ogg`: Opus in Ogg, 16 kHz mono at about 20 kbit/s (about 75 KB for 30 seconds). As `speech.wav`, `audio/wav` (16-bit PCM, 16 kHz, mono, under 1 MB) instead while the compression library is not on the phone, to an address ending in `/inference`, and to a server that could not read the Opus file |
| `model` | when **Model** is filled in | the text of the field |
| `language` | when **Send the keyboard language** is on and Whisper knows the language | an ISO-639-1 code such as `en`, `bn` or `de` |
| `prompt` | when there are words to listen for, or **Prompt** is filled in | your words to listen for, then the text of **Prompt**. See [Words and the prompt](#words-and-the-prompt) |
| `response_format` | always | `json` |

An `Authorization: Bearer <key>` header is added when **API key** is filled in. Clips shorter than 0.3 seconds, and clips with nothing louder than a quiet room in them, are never sent. See [A silent clip types nothing](/tools/whisper/#details--edge-cases).

**Reply.** HTTP 200 with `{"text": "the words"}`. Other fields are ignored. A plain-text body is accepted too, and is used as the transcript.

**Errors.** A 400, 415 or 422 answer to an Opus file is taken to mean the server cannot read Opus: the same phrase is sent again at once as WAV, and once a WAV is read, that address gets WAV for as long as the keyboard keeps running. Otherwise any status outside 200–299 fails the phrase. When the body is `{"error": {"message": "…"}}`, that message is what the voice panel shows. Otherwise the panel shows the keyboard's own wording for the status (401 and 403 read as a rejected key, 429 as a rate limit).

Timeouts are 10 seconds to connect and 60 seconds for the reply.

## Words and the prompt

A server gets the [words to listen for](/tools/voice/#words-to-listen-for) inside OpenAI's `prompt` field, followed by whatever you type into **Prompt**. The model reads the prompt as the text that came before your clip, so a name in it is a name the model has just "seen" spelled your way. The **Prompt** field is also where to set a style, such as "Casual chat between friends." or a sentence in the spelling you want.

Whisper models, which is what most servers run, read only the last 224 tokens of the prompt, and drop the rest without saying so. That's a limit of the model: Whisper's decoder has room for 448 tokens and gives half of them to the prompt. 224 tokens is roughly 150 short English words, fewer for long names or for scripts that take several tokens a character, so it can't hold a whole dictionary. Newer models such as OpenAI's `gpt-4o-transcribe` read far more.

So the keyboard builds the prompt for that limit. It sends at most 150 words, and puts them in order of importance with the most important at the end, where a Whisper model keeps them: your **Prompt** text last, then your own list, then the words you added by hand and the personal dictionary, and the learned words at the front. When a Whisper server has to cut, it cuts the learned words first. The whole prompt is capped at 4,000 characters.

## Privacy

With this engine, the recording of each phrase leaves your phone. It goes to the address you typed, or the one you set for the language you are typing in, and nowhere else, and only after you start dictating. Nothing is sent in the background. The API keys are stored with your other settings and are left out of backups unless you choose to include API keys. See [Network policy](/privacy/network/).

An `http://` address sends the audio unencrypted. That is fine on your own network. Use `https://` for anything reached over the internet.

With **Listen for my words** on, the prompt carries up to 150 of your own words, as described in [Words and the prompt](#words-and-the-prompt). Turn it off, and leave **More words to listen for** and **Prompt** empty, and no prompt is sent at all.

Voice typing stays off in password fields, whichever engine is chosen.

## Details & edge cases

- **Mobile data.** [Data saver](/privacy/data-saver/) has a **Transcription server** row. It is allowed by default. Set it to **Ask each time** and the first phrase on mobile data is held with a note. Pressing the microphone again sends it and allows the rest of that session. **Turn off** stops the engine on mobile data.
- **No address yet.** Choosing the engine without filling in the address makes the voice panel say so, with a shortcut to these settings and a button that switches back to the system recognizer.
- **Server unreachable.** The panel shows why: no connection, a timeout, or a server that refused the connection. Nothing is typed and the rest of your text is untouched. Press the microphone to try again. With [Use on-device models offline](/privacy/data-saver/#with-no-connection) on and a [Whisper model](/tools/whisper/) downloaded, the phrase is transcribed on the phone instead, and with no connection at all the next phrase goes to the Whisper model, or to the voice typing of your phone, from the start.
- **No live words.** Like offline Whisper, the server gets the whole phrase at once, so nothing appears in the field while you speak.

## How much it sends

Each phrase goes as Opus, the codec voice calls use, at about 20 kbit/s: around 75 KB for 30 seconds of speech, where the same recording as WAV is just under 1 MB. On 73 LibriSpeech recordings (8 minutes) the Opus files were 12.7 times smaller, and a Whisper small.en server got 5.74% of the words wrong from them against 5.65% from WAV: one word more in 1,150.

The compression library is one of the [feature libraries](/privacy/network/#downloads-dictionaries-models-and-addons), fetched the first time you dictate with this engine (from Play on a Google Play build, and on an F-Droid build only after you turn on **Download feature libraries**). Until it is there, the phrase goes as WAV.

[Network activity](/privacy/network-activity/) shows the saving on each request: press a Transcription server row, and **Saved** says how much less was sent than the WAV would have been.
