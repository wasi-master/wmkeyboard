Typing never needs the internet. Layouts, prediction, autocorrect, gesture typing, learning, the clipboard, snippets and every tool that works on the device run the same with the phone in airplane mode. What the internet is for is fetching things: word lists and word pairs, emoji names, voice and AI models, text recognition data, GIFs. This page is about getting those onto a phone that can't fetch them itself, whether it is offline for now or running the [build with no internet permission](/development/building/#a-build-with-no-internet-permission) that every GitHub release carries.

## The offline build

Every GitHub release has an **offline** build: the standard app with the internet permission taken out, so Android refuses every connection it tries. From 0.6.4 it is about the size of the standard build, because it leaves out the same two things the standard build downloads only when you want them:

- **Interface languages.** The app's own screens are in English. Each of the other 48 languages is one small file on the release page, `wmkeyboard-<version>-vc<code>-lang-<code>.apk`, about 2 MB.
- **Feature libraries.** The native code behind offline voice typing, grammar and spell checking, the scanners, handwriting, the RIME and Mozc engines, Firefox Translations and on-device AI. Each library is one file.

Typing, prediction, autocorrect, gesture typing, the clipboard and every tool that needs neither of those work straight after install. For the rest, fetch the files you want on another device and import them; nothing is pushed at you that you never use. Up to 0.6.3 the offline build carried all of it: 275 MB for `arm64-v8a`, against about 22 MB now.

### Interface languages

<SettingsPath path="About / App language" />

Pick a language under **App language**. If its file isn't on the phone yet, a message names the exact file to get, and the app stays in English for now. Download that file from the release page of the version you have installed (a pack only fits the version it was cut from), move it to the phone, and import it under <SettingsPath path="About / Storage / Import downloaded files" />. **Get the files** on that row opens the release page. Once the pack is in, pick the language again and the screens switch.

The import accepts a pack only if it is signed with the same key as the app and carries this version's number, so a pack from another release, or from anyone else, is refused.

Language packs need Android 11 or later, which added the way for an app to load another APK's text. **On Android 7 to 10 the offline build shows English only.** For those phones each release also has an **offline, all languages** build, `full-intl-nointernet-universal.apk`, with all 48 languages built in. It is the same app otherwise, it takes feature libraries the same way, and it installs over the offline build and back without losing a setting. Take it on Android 11 and later too if you would rather not import a language.

### Feature libraries

<SettingsPath path="Privacy / Downloads / Feature libraries" />

On the offline build, **Feature libraries** says how many of the app's libraries are on the phone. **Get the files** lists every one still missing, each with its exact file name, size and address, a copy and an open-in-browser button, and **Share** to send the list to another device. **Import** takes the files once they are on the phone. A feature that needs a missing library says so where you use it, with the same **Get the files** button limited to that feature's own files, instead of offering a download that cannot work. The scanner panel in the keyboard points here.

The libraries come from two places:

- **The project's own libraries** (whisper.cpp, ExecuTorch, Sherpa, Harper, Hunspell, Tesseract, RIME, Mozc, zinnia, Bergamot, llama.cpp, OpenCV, zxing-cpp and the others) are on the data repository's [`natives` release](https://github.com/wasi-master/wmkeyboard-data/releases/tag/natives), each named `<sha256>-<library>.so`. Download the one listed for your phone; the list already picks your phone's ABI.
- **Other vendors' libraries** (Google's ML Kit, LiteRT and LiteRT-LM, Microsoft's ONNX Runtime behind Sherpa and the neural phonetic suggestions, Qualcomm's NPU runtime) can't be republished, so the list links the vendor's own package, an `.aar` file on Google's Maven repository or Maven Central. Import the `.aar` whole. The keyboard takes out the one library it needs for your phone and leaves the rest.

On the `natives` release the project's own files carry their checksum in front of the name, so look for the name after it; the other vendors' files are the ones inside their `.aar`. A feature that needs a library names it in its banner too.

A version that changes a library pins the new file, so after updating the offline build, a feature whose library changed asks for it again. The old copy is deleted.

## Importing instead of downloading

Everything the keyboard downloads is a file with a public address. Fetch it anywhere, in a browser on this phone or on a computer, move it to the phone, and import it. The keyboard installs it through the same code the download would have used: the same parsing, the same checksum where the download has one, and the same place on disk. An imported word list is indistinguishable from a downloaded one.

On the offline build these screens have no **Download** button, because it could only fail, and the import row is always shown whatever the settings depth. A few things have no import yet and say so on their screen: Read back's offline voices, the strong noise reduction model, the semantic search models and the sticker generator's models.

Each screen that downloads something has an import row with two buttons:

- **Get the files** lists what that screen would download, with an open-in-browser and a copy button beside each file, and **Share** to send the whole list to another device. The browser does the fetching, so this works on a build with no internet permission too.
- **Import** opens the file picker. Pick one file or many, loose or in a zip. Afterwards a report lists each file and what became of it.

| What | Where the import row is | Files |
|---|---|---|

The Storage row takes every kind of file, so it is the one to use for a folder of mixed downloads. It is also the only way in for an on-device AI model other than the AI model screen's own import, and for the sticker editor's background remover (`u2netp.tflite`).

A handwriting model is made of two or three files, which Google publishes for ML Kit to fetch: a small recogniser spec, the recogniser itself (shared by every language in one script) and, for most languages, a word list. **Get the files** lists them per language. Leave them as `.zip` files, loose or zipped together; the import checks each against the SHA-1 checksum ML Kit ships with. Once every file a language needs is in, its model installs the way a download would, through ML Kit itself, and the import answers ML Kit's requests for those files from the phone. Files that arrive before the rest of their set are kept until it is complete. The import needs no network and no internet permission. On the offline build the recogniser also needs its feature library, `libdigitalink.so`, read out of ML Kit's `digital-ink-recognition` `.aar`. Files imported before it are kept, the report says the library is what's missing, and the model installs as soon as the library is imported.

Files are recognised by name, which is the name they are published under. Renaming one (a browser adding `(1)` to a second download, for instance) makes it unrecognisable, and the report says so rather than guessing. The exception is a `.so` library, Google's gesture library or a feature library, which is also told by its checksum.

## Language packs

A language pack is one zip holding everything a language downloads: its word lists, its word-pair data, its emoji names, and for Chinese, Japanese and Cantonese their conversion tables. There is one per folder of the [data repository](https://github.com/wasi-master/wmkeyboard-data), named `wmkb-lang-<code>.zip`, on its [language packs release](https://github.com/wasi-master/wmkeyboard-data/releases/tag/language-packs). **Get the files** on a language's screen links its own pack directly. The packs are rebuilt whenever the data changes. A pack, or one of its files on its own, can also be opened straight from a file manager or a chat app: WM Keyboard asks before installing it, then shows the same report. The same works for every other file in the table above, and the question names what the file is: a model, a dictionary, a GIF pack, RIME schemas, an interface language, a feature library or Google's gesture library. A `.so` file is never offered as language files.

Some folders serve two languages. The Bangla pack also carries Banglish, and importing it installs both (of Bangla's two word lists, the counted `bn_full_v2`; `bn_full` is there for older app versions), along with desktop Avro's dictionary (`bn_avro_dictionary.txt.gz`) for the Avro candidate list and the Khipro spellings (`bn_khipro_glide.txt.gz`) that glide typing on Khipro reads. The packs of Bangla, Assamese, Hindi, Urdu, Persian, Arabic and the eight Indic phonetic languages also carry the phonetic index built over the word list (`<code>_phonetic_v1r1.wmpi.gz`, `v1r2` for Bangla and Assamese), which the phonetic layout reads instead of folding the list on the phone. Where a pack holds more than one word list for a language, the import asks which one to install, since a language uses one at a time. English's pack has five: the AOSP lists for **United States**, **United Kingdom**, **Canada** and **Australia**, and the counted **Frequency** list. The dialog opens on the one a download would start on, the others are listed as not used, and **Cancel** installs none of them. To switch later, import the pack again and pick another; the new list replaces the old one. The word list is kept at the size you last chose for downloads (Large, 300,000 words, until you pick another), the same cap a download applies.

## Voice models

A whisper.cpp Whisper model is one `.bin` file, and it is only installed if it matches the SHA-256 the catalog has for it. On the offline build it runs on the whisper.cpp feature library (`libwmwhispercpp.so`), not on LiteRT: the banner above the models names that file once a `.bin` model is on the phone. A LiteRT Whisper model is two files: the graph and a vocabulary file that several models share. Import both together, or in either order. A vocabulary imported first waits for its model; a model imported without its vocabulary is placed and reported as still needing it, and becomes ready the moment the vocabulary arrives. Graphs are matched on their exact size as well as their name, because two different files have been published as `whisper-tiny.en.tflite` and only one of them works.

The [Whistle](/tools/whistle/) model is one file, `whistle.cact`. Only the exact file the app downloads is accepted: its SHA-256 is checked before it is put in place.

The models of the other offline engines, [Asr4All](/tools/asr4all/), Parakeet, Moonshine, [Sherpa](/tools/sherpa/) and [Omnilingual](/tools/omnilingual/), import from the **Import from a file** row at the top of each engine's model list. **Get the files** lists every file of every model not on the phone, straight from Hugging Face at the revision the app pins. A model is several files (a tokenizer, the model itself, for Sherpa a voice detector too), and it is ready once all of them are in. Each file is told by its size and SHA-256 rather than its name, because names like `tokens.txt` and `model.pte` repeat from model to model; a renamed file still installs. A file several models share, such as Sherpa's `silero_vad.onnx`, goes only to the models whose other files you have imported, so import it together with them.

## Translation models

The offline build translates with Firefox Translations, on a 64-bit phone with Android 9 or later. To set it up:

1. Under <SettingsPath path="Tools / Translate / Providers / On device (Firefox Translations)" />, press **Get the files** on the banner, get `libwmbergamot.so` and import it.
2. Press **Get the files** on the import row below the directions, and download every file of each direction you want. French into German needs French → English and English → German.
3. Press **Import** and pick them all. A direction is ready once it has all its files. Translate's language menus then list it.

Mozilla's addresses end in long codes rather than names, so the app knows each file by its size and SHA-256, whatever your browser calls it. Files imported before the library wait for it.

## GIF packs

The GIF panel can show packs of GIFs kept on the phone, with no key and no connection. It reads [CleverKeys' offline GIF packs](https://github.com/tribixbite/CleverKeys/releases/tag/CleverKeys-GIF): download one in the browser and import it under <SettingsPath path="Tools / GIFs / Offline GIF packs" />. Once a pack is installed, the GIF panel gains an **Offline** chip beside any online source, with its own grid, search and category chips. See [GIFs](/emoji/gifs/#offline-gif-packs).

Only the **Discord community** packs carry animated GIFs. The **thumbnail** packs hold 80-pixel stills, previews with nothing behind them to send, so the import refuses them and says why.

## What cannot work offline

- **ML Kit and NLLB-200 translation.** Google's ML Kit downloads and keeps its language models itself, with no way to install one from a file, and NLLB-200's 630 MB model has no import. The offline build [translates with Firefox Translations](#translation-models) instead.

Everything reaching an online service (web and image search, GIFs from KLIPY or GIPHY, the dictionary and synonyms lookups, cloud AI providers, the currency rates, backups to a cloud account) needs the connection by definition. On a build with no internet permission those say that the build cannot connect, rather than waiting for a network that will never come. The Dictionary tool is the exception once an [offline dictionary](/tools/search/#offline-dictionaries) is imported: it then defines English words from the phone.

## Details & edge cases

- **An import replaces what is there.** Importing a word list over a downloaded one swaps it, as a second download would. An import also undoes an earlier Delete, so the automatic downloads that were told to leave that language alone count it as present again.
- **Nothing is half-installed.** Each file goes through a temporary copy and is renamed into place only once it is whole, so a failed or cancelled import leaves the previous state untouched.
- **An import waits for a download of the same thing.** Both would write the same file, so while a word list, voice model or conversion table is downloading, an import of that kind is refused with a note to try again.
- **Checksums where the download has them.** Conversion tables and the background remover are checked against the checksum the app ships with, and a file that differs is refused. Word lists, word pairs and emoji names are checked by parsing them; a file that does not parse is reported as damaged.
- **Space.** A picked file is copied into the app before it is installed, so an import needs room for about twice its size for a moment.
