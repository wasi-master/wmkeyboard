**Effective 26 November 2026.** This policy covers the WM Keyboard Android app
(`com.wasimaster.wmkeyboard`) and this documentation site. WM Keyboard is
written and published by Wasi Master, an individual developer.

:::note[This page covers the Google Play and GitHub builds]
The F-Droid build and the others are not the same app underneath, so they get
one policy each rather than one policy with a page of footnotes.

This page is every build but F-Droid's: the one on Google Play, and the
standard and offline APKs on the GitHub releases page. It includes handwriting, OCR, QR and document
scanning, sticker background removal, grammar checking, offline Whisper
dictation and on-device AI. The handwriting, scanning and background-removal
features run on Google's ML Kit. From 0.6.8 the app cuts out the reports ML
Kit sends Google about its own use, and **Privacy › Google libraries** can
switch ML Kit and Google's other libraries off altogether. What still reaches
Google, at either setting, is under
[Google components inside the app](#google-components-inside-the-app).

If you installed from F-Droid, you have a build that ships none of the ML
Kit features, and no ML Kit, Play library or Google sign-in code at all. Read
[Privacy policy (F-Droid edition)](/privacy/policy-fdroid/) instead. The app
tells you which one you have under About: the version line says F-Droid on
that one.
:::

The rest of this section explains the same subject in more depth and with
screenshots. This page is the short, formal version, the one the Play listing
links to.

## The summary

WM Keyboard collects nothing. There is no account, no advertising, no
tracking, and no analytics or crash reporting that this project receives. What
you type is processed on your device and stays there. The one thing the app
ever sends to a server of this project is a name you typed yourself, after you
chose to tip and asked to be listed, with a message if you wrote one; see
[Tips](#tips).

One caveat: some features are built on Google's ML Kit and on Google Play
services. The app cuts out ML Kit's usage reports and its translator's
requests to Firebase, but those features still download their models from
Google, and the parts that run inside Google Play services are Google's code
under Google's own policy. That is Google's collection, not this project's,
and it is spelled out in full under
[Google components inside the app](#google-components-inside-the-app). With
**Privacy › Google libraries** set to **Off**, none of those Google components
runs, and free software does their work instead.

The app does not sell, rent or share personal information. Apart from a
tipper's chosen name, it does not receive any in the first place.

## What stays on your device

The keyboard writes several things to its own private app storage. None of it
is transmitted anywhere by the app.

- **Learned words and word pairs.** Words you use that were not already in a
  dictionary, plus the bigrams, trigrams and skip-grams (the word two or three back paired with the one that followed) used to predict and rank the next word.
- **Clipboard history**, if you have the clipboard tool enabled, along with
  anything you pinned.
- **Typing statistics**, such as counts of keystrokes and words, if you have
  statistics enabled.
- **Your settings**, themes, layouts, snippets and personal dictionary
  entries.
- **Downloaded data**, such as dictionaries, emoji keyword packs and voice
  models.

You can delete all of it. Learned data is one confirmed tap on the app's
Privacy screen, and clipboard history and typing statistics each have a clear
action of their own on the storage screen under About. Uninstalling removes
everything the app ever wrote.

Password fields, and any field an app marks as sensitive, are excluded from
learning, suggestions and clipboard capture automatically. Incognito mode
pauses learning and clipboard history everywhere for as long as it is on.
Suggestions keep working, because they are read out of data that is already
there rather than written to it.

Typing itself never uses the network. A set of optional tools do, each one
only while you are actively using it:

| Web and image search | your query | Brave Search, Tavily if you add a Tavily key, Mwmbl, Wiby, Marginalia Search or Wikipedia if you add them, and, through Built-in search (on by default, last in the list), Mwmbl, Marginalia Search, Wikipedia and Wiby at once, and Wikimedia Commons for pictures |
| GIF and sticker search | your query | KLIPY, GIPHY, and the Internet Archive's GifCities if you turn it on |
| Dictionary | one word | `kaikki.org`, `en.wiktionary.org`, `api.dictionaryapi.dev`, `api.urbandictionary.com` if you turn it on, in the order you set |
| Synonyms, from the word menu | one word | `api.datamuse.com`, `kaikki.org`, `api.dictionaryapi.dev`, in the order you set |
| Encyclopedia | your query | Wikipedia |
| Weather | a location you entered; with **Weather on events** on, the places of your calendar events | Open-Meteo |
| Currency and crypto rates | nothing identifying | `open.er-api.com`, `api.coinbase.com` and their fallbacks |
| Photo backgrounds | your search terms | Unsplash, Pexels |
| AI writing tools | the text you ran an action on | the provider you chose, using your own API key |
| AI chat's Deep research and Summarize | the search queries the model planned, and an ordinary request for each page read; the pages' text then goes to your AI provider with your question | your web search provider, and the websites of the pages read |

Four of these can fire without you opening a tool under default settings.
They are the weather smart chip, the currency smart chip, automatic language
data downloads, and the dictionary tool's look-up-at-cursor. Each has its own
switch. [Network policy](/privacy/network/)
documents every one of these in full, including what is cached and for how
long, and [Permissions](/privacy/permissions/) covers what each Android
permission is for.

When you use one of these tools, your data is handled by that service under
its own privacy policy, not this one. The app ships no key for the AI
providers: those only work if you supply your own.

## Tips

The Google Play build can take a tip through Google Play billing, under
About › Supporters. Google Play handles the payment, under
[Google's privacy policy](https://policies.google.com/privacy). This project
never sees your card, your Google account or your email address.

If you type a name to be listed, then once Google Play confirms the payment
the app sends that name, the message you typed (if any) and the purchase
receipt (the product and Google Play's purchase token) to
`wmkeyboard.pages.dev/api/play-tip`. The site asks Google whether the receipt
is a real, paid order and, if it is, adds the name, the message, the word
"Tip", the tier's list price in US dollars and the date to the public
[Supporters](/start/supporters/) page. The app's own list shows the name only.
With **Stay anonymous** on, or the name left empty, nothing is sent.
Until the site has answered, the app keeps the name and receipt on your device
and tries again when you next open Supporters, for up to 30 days. To have a
name removed, email the address under [Contact](#contact).

## Backups

Backups are optional and written to the destination you choose. That can be
local storage, a cloud drive you connect, a WebDAV server, an S3-compatible
bucket, an SFTP, SMB or FTP server you run, a Git repository you own, or a
folder in your own mail account. By default the file is plain JSON. Turn on
a backup passphrase and it is encrypted with AES-GCM under a PBKDF2
key (HMAC-SHA256 for most backups, HMAC-SHA512 for large ones). Nothing is uploaded anywhere by default and no copy is sent to the
developer. See [Backup and restore](/privacy/backup/).

## Children

WM Keyboard is not directed at children and collects no data from anyone,
including children. The only thing ever received is the name and message a
tipper chose to have listed, described under [Tips](#tips), and both are
removed on request.

## Google components inside the app

Four Google components the app uses can reach Google on their own, without
going through any code here. They cannot see what you type, and this project
receives nothing from them.

- **ML Kit** powers handwriting input, OCR, QR and barcode scanning, the
  document scanner, sticker background removal and on-device translation, in
  every build but F-Droid's.
  Google
  [states](https://developers.google.com/ml-kit/android-data-disclosure) that
  its SDK reports device information (make, model, OS build, available ML
  accelerators), this app's package name and version, a per-installation
  identifier, timing and error information, and the size and settings of what
  was processed, as diagnostics and usage analytics, whenever one of those
  features runs. From 0.6.8 the app switches those reports off: the two calls
  ML Kit sends them through are replaced, when the app is built, with ones
  that send nothing. ML Kit's on-device translator, which Google lists as
  using Firebase installations and Remote Config, would also register a
  per-installation identifier with Firebase and fetch its settings with it;
  the app refuses both requests, as if the phone were offline, and the
  translator keeps its built-in settings. What still reaches Google:
  - model downloads, such as a handwriting language or a translation
    language, from Google's servers the first time you need one;
  - the parts that run from Google Play services rather than from the app: on
    the Google Play build the text and barcode readers, and on any phone with
    Play services the Chinese, Japanese, Korean and Devanagari text readers,
    the document scanner and the one-tap background remover. That is Google's
    code in Google's own app, and what Play services records is covered by
    [Google's privacy policy](https://policies.google.com/privacy).

  The content of the image, ink or document is not part of any of it.
- **Android AICore**, on phones that have it, runs Gemini Nano when you pick
  **Gemini Nano (on this phone)** in the app's AI chat or Settings assistant.
  The conversation goes to AICore, a system service on the phone, and is
  answered there; this app sends it nowhere else. AICore downloads and updates
  the model itself, and its use comes under Google's terms for AICore and
  Gemini Nano. The app talks to it through ML Kit's GenAI library, whose usage
  reports are switched off with the rest of ML Kit's. Nothing reaches AICore unless
  you pick Gemini Nano and send a message.
- **Downloadable fonts.** Some scripts' default keyboard font, and every
  Google font in the theme editor, are fetched by Google Play services' font
  provider. It receives the font name and this app's package name.
- **Google Play libraries** in the Play Store build check for app updates,
  fetch the on-device AI runtime when you first use it, and take a tip
  through Google Play billing if you choose to leave one.

**Privacy › Google libraries** decides how much of this runs. **No
analytics**, the default, is what the list above describes. **Off** keeps ML
Kit, LiteRT, LiteRT-LM, Gemini Nano, the Google Home APIs, Google's WebRTC
library and Play services' scanner, background remover, sign-in and fonts
from running at all, so none of their traffic happens: the free software of
the F-Droid build does that work, and a feature with no free stand-in is not
offered. The Play Store build keeps the Google Play libraries in the last
item, because they install and update the app. The keyboard restarts when you
change the setting.

Connecting Google Drive as a backup destination adds a Google sign-in and
ordinary Drive API calls, and only if you connect it.

ML Kit, AICore and the Play libraries are specific to this edition: the
F-Droid build has no ML Kit, no Play libraries and no Google sign-in compiled
into it at all, so it never talks to AICore.
Downloadable fonts are the exception, since that request goes to a system
provider rather than to code the app bundles, so the F-Droid build makes it too.
See [Privacy policy (F-Droid edition)](/privacy/policy-fdroid/).
