Plug in a Bluetooth or USB keyboard and WM Keyboard keeps running underneath rather than getting out of the way. Autocorrect, suggestions and transliteration all work on physical keystrokes exactly as they do on the soft keys. A leader key opens any tool without your hand leaving the keys.

## Typing on a physical keyboard

<SettingsPath path="Typing / Physical keyboard / Process the physical keys" />

With **Process the physical keys** on (the default), a key you press on a physical keyboard runs through the same code path as a tap on the screen. Phonetic layouts transliterate as you go, words compose for suggestions, autocorrect fires on <KeyCap>Space</KeyCap>, and <KeyCap>⌫</KeyCap> undoes a swipe or a correction instead of just deleting a character. **Wrap the selection with brackets** carries over too, and it's on by default: select some text, type a bracket (either half) or a quote on the physical keyboard, and it wraps the selection the same way a tap would.

Turn the toggle off and physical keys type their raw characters straight into the field. The keyboard's own layout owns input entirely from there, and correction is the system's business rather than WM Keyboard's.

Two things stay true no matter how this toggle is set:

- **Shortcuts, navigation and function keys always go straight to the app.** <KeyCap>Ctrl</KeyCap>+<KeyCap>C</KeyCap>, the arrow keys, <KeyCap>Tab</KeyCap>, <KeyCap>Esc</KeyCap> and forward-delete are never intercepted for typing. Only actual character keys are. AltGr combinations look like a shortcut and aren't one: a German keyboard's AltGr+Q for "@" arrives as Ctrl and Alt together, and the keyboard reads that as a character, decoding it the way the system does.
- **Password fields and structured fields never get autocorrect help.** Email, URL, number, phone, date, time and date-time fields, and anything marked as a password, always take raw physical typing. There's nothing to transliterate or correct in a field that isn't ordinary prose.

Android composes a physical dead key (an accent key that combines with the next letter) before the keystroke reaches the keyboard, so WM Keyboard doesn't run its own accent logic on top. You get the accented character the same way any other app would see it. One soft-keyboard-only behavior is worth knowing: a bare press of the physical <KeyCap>Shift</KeyCap> key is only a modifier, so it doesn't cycle a selection's capitalization the way tapping the on-screen <KeyCap>Shift</KeyCap> key does.

## Opening tools with the leader key

<SettingsPath path="Typing / Physical keyboard / Tool shortcuts list" />

<PhoneFrame side caption="Hotkey badges under the toolbar icons after double-tapping Ctrl.">
  <Shot id="typing/hardware-tool-picker" alt="The tool-picker overlay after double-tapping Ctrl, showing the bound letters." />
</PhoneFrame>

**Tool shortcuts** (on by default) let you open any tool without touching the screen at all. Double-tap <KeyCap>Ctrl</KeyCap>, a combination nothing else uses, and every button on the keyboard sprouts a small badge under its icon showing the key that operates it. Press that key and the button fires. Press nothing and the badges disappear on their own.

The badges cover everything on screen:

| Where | Key |
| --- | --- |
| Toolbar icons | <KeyCap>1</KeyCap> onward, counting from the toolbox button at the start |
| Toolbox tools | the tool's own letter, or <KeyCap>Shift</KeyCap>+a spare key for the ones with no letter (all 26 letters first, then the digits) |
| Symbol row | <KeyCap>Shift</KeyCap>+a letter |
| Emoji row | <KeyCap>Shift</KeyCap>+<KeyCap>1</KeyCap> onward, counting from the left like the toolbar |
| Suggestions | <KeyCap>1</KeyCap> to <KeyCap>9</KeyCap>, left to right (see below) |

The badges spell their modifier out, `Ctrl+2` and `Shift+Q`, because those are the names printed on a PC keyboard. <SettingsPath path="Typing / Physical keyboard / Write the modifier names" /> swaps them for the shorter `⌃` and `⇧` glyphs if you'd rather have the space back.

<SettingsPath path="Typing / Physical keyboard / Time to press a key" /> sets how long they stay up: eight seconds by default, anywhere from one to thirty. Keep it long while you're learning them and short once you aren't. The keyboard does nothing else until the time runs out or you press a key.

<KeyCap>T</KeyCap> still opens the full toolbox from anywhere, and <KeyCap>?</KeyCap> opens the cheat sheet: a complete legend of every key, including the tools that aren't on screen to wear a badge. While the badges are up, a small `? for all keys` pill in the bottom-right corner points at it. The legend has a close button of its own, so you're never stuck in it without a keyboard.

### Ctrl and a number, with no leader

<SettingsPath path="Typing / Physical keyboard / Ctrl + number opens a toolbar tool" />

The toolbar's numbers also work as a direct chord, so the common tools are one keystroke away rather than three. <KeyCap>Ctrl</KeyCap>+<KeyCap>1</KeyCap> is the toolbox button, <KeyCap>Ctrl</KeyCap>+<KeyCap>2</KeyCap> the first tool after it, and so on to <KeyCap>Ctrl</KeyCap>+<KeyCap>0</KeyCap> for the tenth button. Anything past the tenth stays reachable through the toolbox.

That's the one setting here worth a second thought before you leave it on. Browsers and editors use <KeyCap>Ctrl</KeyCap>+number to switch tabs, and while you're writing in a text field the keyboard takes the key first. Turn it off and the same numbers still work after the leader key.

### The tool letters

<PhoneFrame side caption="The Tool shortcuts list screen: every tool with the letter that opens it.">
  <Shot id="typing/hardware-shortcuts-list" alt="The Tool shortcuts list screen: every tool with the letter that opens it." />
</PhoneFrame>

The default letter for each tool is close to its own initial, wherever that letter was still free:

| Key | Tool | Key | Tool |
| --- | --- | --- | --- |
| <KeyCap>A</KeyCap> | AI writing tools | <KeyCap>O</KeyCap> | Settings shortcut |
| <KeyCap>B</KeyCap> | Power saving | <KeyCap>P</KeyCap> | Password generator |
| <KeyCap>C</KeyCap> | Clipboard | <KeyCap>Q</KeyCap> | QR code generator |
| <KeyCap>D</KeyCap> | Dictionary | <KeyCap>R</KeyCap> | Translate |
| <KeyCap>E</KeyCap> | Emoji | <KeyCap>S</KeyCap> | Snippets |
| <KeyCap>F</KeyCap> | Fancy text | <KeyCap>U</KeyCap> | Unit converter |
| <KeyCap>G</KeyCap> | GIFs | <KeyCap>V</KeyCap> | Voice typing |
| <KeyCap>H</KeyCap> | Hide keyboard | <KeyCap>W</KeyCap> | Web search |
| <KeyCap>I</KeyCap> | Image search (web search's Images tab) | <KeyCap>X</KeyCap> | Text editing |
| <KeyCap>J</KeyCap> | Apps | <KeyCap>Y</KeyCap> | Special symbols |
| <KeyCap>K</KeyCap> | Stickers | <KeyCap>Z</KeyCap> | Undo |
| <KeyCap>L</KeyCap> | Calculator | | |
| <KeyCap>M</KeyCap> | Media controls | | |
| <KeyCap>N</KeyCap> | Numpad | | |

Open **Tool shortcuts list** to change any of it. (The screen is reachable only while Tool shortcuts is on.) Tap the shortcut key row to pick a different double-tapped modifier, <KeyCap>Ctrl</KeyCap>, <KeyCap>Alt</KeyCap> or <KeyCap>Shift</KeyCap>, or to capture an arbitrary chord live from an attached keyboard. Tap any tool's row to type a new single letter or digit for it. **Reset to defaults** puts every letter and the shortcut key itself back the way they started.

<KeyCap>T</KeyCap> and <KeyCap>?</KeyCap> are reserved and can never be bound to a tool: they always open the toolbox and the cheat sheet, respectively. The full binding table and cheat sheet also live in [Hardware shortcuts](/reference/shortcuts/).

There are dozens of tools and only 25 bindable letters on the bare tier (<KeyCap>T</KeyCap> is spoken for), so "give everything its own key" is arithmetically impossible on one tier. The ones with no letter of their own get a <KeyCap>Shift</KeyCap>+key assigned automatically while the toolbox is open, drawing on the letters first and then the digits. The Shift tier uses all 26 letters, <KeyCap>Shift</KeyCap>+<KeyCap>T</KeyCap> included, because only the bare <KeyCap>T</KeyCap> is reserved. That's what the badges in the grid are showing. They follow the grid's order, so they stay put unless you rearrange the toolbox itself.

## Symbols and emoji from the keyboard

While the toolbox is closed, the same <KeyCap>Shift</KeyCap> tier goes to the symbol row and the emoji row. Double-tap <KeyCap>Ctrl</KeyCap>, then press <KeyCap>Shift</KeyCap> with the key shown under the cell you want, and it's inserted.

The symbol row takes the letters and the emoji row takes the digits: <KeyCap>Shift</KeyCap>+<KeyCap>1</KeyCap> for the first emoji, counting from the left exactly the way the toolbar's numbers do. Letters against digits means the two pools can never collide, so adding a character to a symbol set never renumbers the emoji beside it.

An open toolbox takes the whole tier for itself and the rows drop their badges while it's up. That's deliberate: sharing would move the rows' keys around every time a panel opened, and a key that moves is a key nobody learns.

## macOS shortcuts

<SettingsPath path="Typing / Physical keyboard / macOS shortcuts" />

Off by default, and worth turning on for a keyboard built for a Mac. With it on, Command (the key beside the space bar, which Android sees as Meta) and Option behave the way they do on macOS:

| Chord | Does |
| --- | --- |
| <KeyCap>⌘</KeyCap>+<KeyCap>C</KeyCap> / <KeyCap>V</KeyCap> / <KeyCap>X</KeyCap> / <KeyCap>A</KeyCap> | Copy, paste, cut, select all |
| <KeyCap>⌘</KeyCap>+<KeyCap>Z</KeyCap> / <KeyCap>⌘</KeyCap>+<KeyCap>Shift</KeyCap>+<KeyCap>Z</KeyCap> | Undo, redo |
| <KeyCap>⌘</KeyCap>+<KeyCap>←</KeyCap> / <KeyCap>→</KeyCap> | Start, end of the line |
| <KeyCap>⌘</KeyCap>+<KeyCap>↑</KeyCap> / <KeyCap>↓</KeyCap> | Start, end of the text |
| <KeyCap>⌥</KeyCap>+<KeyCap>←</KeyCap> / <KeyCap>→</KeyCap> | One word left, right |
| <KeyCap>⌥</KeyCap>+<KeyCap>⌫</KeyCap> | Delete the word before the cursor |
| <KeyCap>⌘</KeyCap>+<KeyCap>⌫</KeyCap> | Delete to the start of the line |

Hold <KeyCap>Shift</KeyCap> with any of the moves to select instead. <KeyCap>Ctrl</KeyCap> keeps its usual meaning throughout. On a Mac it's a separate modifier with its own habits, and an app that already handles <KeyCap>Ctrl</KeyCap>+<KeyCap>C</KeyCap> should keep getting it. Every other Command chord (<KeyCap>⌘</KeyCap>+<KeyCap>F</KeyCap>, <KeyCap>⌘</KeyCap>+<KeyCap>S</KeyCap>) goes straight to the app, and some devices let the system claim a few Command chords, which never reach the keyboard to be remapped at all.

One deliberate difference from the on-screen long-press shortcuts: <KeyCap>⌘</KeyCap>+<KeyCap>C</KeyCap> with nothing selected does nothing, rather than selecting the whole field first. That's what every other keyboard on a Mac does, and quietly copying a half-written message is a poor surprise.

## Switching language

<SettingsPath path="Typing / Physical keyboard / Ctrl+Space changes the language" />

A keyboard with its own language key (a globe key, or the <KeyCap>한/영</KeyCap> key on a Korean keyboard) can always switch. Press it and the keyboard moves to the next enabled language, flashing a small list so you can see where you landed. With [🌐 goes back to the last language](/languages/switching/#going-back-to-the-last-language) on, it goes back to the language you used last instead, and quick presses go further back. That needs no setting and can't collide with anything, since apps have no use for the key. A few keyboards wire <KeyCap>한/영</KeyCap> as a second right <KeyCap>Alt</KeyCap> instead, which the keyboard can't tell apart from the real one. On those, use <KeyCap>Ctrl</KeyCap>+<KeyCap>Space</KeyCap> below.

For every other keyboard there's **Ctrl+Space changes the language**, on by default. <KeyCap>Ctrl</KeyCap>+<KeyCap>Space</KeyCap> works the way <KeyCap>Alt</KeyCap>+<KeyCap>Tab</KeyCap> does for windows. Keep <KeyCap>Ctrl</KeyCap> held and each press of <KeyCap>Space</KeyCap> steps through the list on screen. Add <KeyCap>Shift</KeyCap> to step backward. Release <KeyCap>Ctrl</KeyCap> and you switch to whatever is highlighted. A quick tap-and-release is a one-step switch. <KeyCap>Esc</KeyCap> cancels, and the rows in the list can be tapped too.

One thing to know: some apps want <KeyCap>Ctrl</KeyCap>+<KeyCap>Space</KeyCap> for themselves, code editors especially, where it shows completions. While you're in a text field the keyboard takes it first. If that bites you, this is the toggle to turn off, and the dedicated language key and the spacebar keep working either way. <KeyCap>⌘</KeyCap>+<KeyCap>Space</KeyCap> is untouched regardless, since it belongs to the system's own keyboard switcher. Whether you see the list depends on **Show the keyboard for shortcuts** below. With that off the switch still happens, and you find out from the spacebar label the next time the keys are up.

Some phones never hand <KeyCap>Ctrl</KeyCap>+<KeyCap>Space</KeyCap> to the keyboard at all. Huawei's tablets keep it for their own keyboard, so on a MatePad it does nothing here. For those there's **Ctrl+Shift changes the language**, off by default. Press <KeyCap>Ctrl</KeyCap> and <KeyCap>Shift</KeyCap> together, with no other key, and let go: the keyboard moves to the next language, as on Windows, and flashes the list. A shortcut such as <KeyCap>Ctrl</KeyCap>+<KeyCap>Shift</KeyCap>+<KeyCap>Z</KeyCap> is left alone, because another key came between.

Switching the keyboard's language doesn't by itself change what a physical key types: Android types the character the phone's own physical-keyboard layout gives the key, and on some tablets that layout is stuck on the system language. **Letter keys follow the on-screen layout**, off by default, fixes that. Each letter key then types the letter in the same place on the layout on screen, so <KeyCap>Q</KeyCap> types the first key of the top row, <KeyCap>A</KeyCap> the first of the middle row, and switching language switches the keys with it. Shift and Caps Lock give the capital or the key's shifted character. Digits, punctuation and anything pressed with <KeyCap>Ctrl</KeyCap> or <KeyCap>Alt</KeyCap> keep the phone's layout.

## Driving a tool with the keyboard

<SettingsPath path="Typing / Physical keyboard / Arrow keys move a highlight" />

<PhoneFrame side caption="The focus ring highlighting a result inside an open panel after an arrow-key press.">
  <Shot id="typing/hardware-focus-ring" alt="The focus ring highlighting a result inside an open panel after an arrow-key press." />
</PhoneFrame>

Once a tool is open, **Arrow keys move a highlight** (on by default) lets you drive it without touching the screen. The arrow keys move a highlighted outline over the panel's results, chips or search box. <KeyCap>Enter</KeyCap> activates whatever's highlighted. <KeyCap>Tab</KeyCap> jumps between the panel's sections (search, category chips, then results) once the highlight exists. <KeyCap>Home</KeyCap> and <KeyCap>End</KeyCap> jump to a section's first and last item, and <KeyCap>PageUp</KeyCap>/<KeyCap>PageDown</KeyCap> move four rows at a time through a long grid. The highlight is a filled, outlined ring in your theme's accent color, and it only ever appears after you press a key. It never shows up while you're using the keyboard by touch.

This covers nearly every tool, searchable or not: the AI panel's actions and Replace/Insert buttons, translate's language picker, media controls' transport, the password generator's options, a running plugin's buttons and text boxes, the calendar's month arrows and day grid, the sound & haptics switches and style chips, the weather refresh, the voice tool's mic. The camera and scanner tools join in once they're showing a captured photo or a scanned result. The live viewfinder itself stays touch-only.

The grammar strip is navigable too, with one difference. You're usually mid-sentence while it's open, so the arrows keep moving your cursor. The highlight appears only when you open the tool from the shortcut key, and <KeyCap>Enter</KeyCap> on an issue applies its top suggestion.

A few tools work by typing rather than highlighting. The calculator and the unit and currency converters take digits and operators straight from the physical keys (type `2*3` and the display shows `2×3`), and in the calculator <KeyCap>Enter</KeyCap> is the <KeyCap>=</KeyCap> key. The text-editing and numpad panels stay touch-only on purpose, since a physical keyboard already does everything they offer. The compass, level and moon phase have no buttons at all, and the handwriting canvas is for fingers and pens.

<SettingsPath path="Typing / Physical keyboard / Esc closes the tool" />

**Esc closes the tool** (on by default) makes <KeyCap>Esc</KeyCap> shut whatever panel or picker the keyboard has open. It only consumes the key when the keyboard actually has something open. With nothing open, <KeyCap>Esc</KeyCap> goes straight to the app, so it still stops a page loading or backs out of insert mode in an editor.

## Picking a suggestion from the keyboard

<SettingsPath path="Typing / Physical keyboard / Number keys select suggestions" />

The suggestion strip can't be tapped while you're typing on a physical keyboard, so **Number keys select suggestions** gives you a keystroke instead. It has three modes:

- **Off.** Number keys always type digits.
- **Alt + number**, the default. <KeyCap>Alt</KeyCap>+<KeyCap>1</KeyCap> through <KeyCap>Alt</KeyCap>+<KeyCap>9</KeyCap> commit directly, with no leader key first. Browsers and chat apps sometimes claim Alt+number for tab switching, so this is the one to change if that bites.
- **After the shortcut key.** Double-tap the shortcut key, then press <KeyCap>1</KeyCap> through <KeyCap>9</KeyCap>. Nothing else uses it, at the cost of one extra keystroke. In this mode the bare numbers belong to the strip, so the toolbar's tools rely on the <KeyCap>Ctrl</KeyCap>+number chord above.

In practice the strip is what sets the ceiling, not the digits. It draws between two and six chips (<SettingsPath path="Typing / Suggestions" />, **Number of suggestions**, three out of the box), so the numbers only ever run as far as the words you can actually see.

<SettingsPath path="Typing / Physical keyboard / Show the suggestion numbers" />

In **Alt + number** mode the strip is the one surface that wears its badges all the time: a small `Alt+1`, `Alt+2`, `Alt+3` under the words, for as long as a physical keyboard is attached. That's on by default, and you can turn it off if you'd rather have the clean strip. **After the shortcut key** has no equivalent, because a bare <KeyCap>1</KeyCap> does nothing until the leader is pressed, so its numbers only appear once it is.

The numbers count slots, left to right, not the engine's ranking. That matters if you use <SettingsPath path="Typing / Suggestions / Best suggestion in the middle" />, which draws the runner-up first: the strip still reads 1, 2, 3 across, and <KeyCap>Alt</KeyCap>+<KeyCap>1</KeyCap> commits the leftmost word you can see rather than the one the engine ranked first.

### Pick mode

<SettingsPath path="Typing / Physical keyboard / Pick mode key" />

Pick mode drops the modifier altogether. Choose a **Pick mode key**, press it once, and the bare number row picks suggestions: <KeyCap>1</KeyCap> takes the leftmost word, <KeyCap>2</KeyCap> the next, and <KeyCap>0</KeyCap> the tenth. To type a number while pick mode is on, hold <KeyCap>Shift</KeyCap> with it. <KeyCap>Shift</KeyCap>+<KeyCap>Alt</KeyCap> with a number types the symbol printed on that key, the one plain <KeyCap>Shift</KeyCap> would normally give you, read from your keyboard's own layout. Press the pick mode key again to turn the mode off. A short message says which way it went, and the strip numbers its words with bare digits for as long as the mode is on.

The key can be any chord with <KeyCap>Ctrl</KeyCap>, <KeyCap>Alt</KeyCap>, <KeyCap>Shift</KeyCap> or <KeyCap>Meta</KeyCap>, a double-tapped modifier, or <KeyCap>F1</KeyCap> to <KeyCap>F12</KeyCap> or <KeyCap>Insert</KeyCap> on its own. It can't be the shortcut key that opens the tools. There's no pick mode key until you set one.

Since a physical keyboard normally hides the on-screen keyboard, the suggestion strip comes up on its own while pick mode is on, without the keys. A number whose slot is empty types itself, so a PIN or phone-number field, which has no suggestions at all, still takes digits. Holding a number down picks once rather than once per repeat. Pick mode stays on as you move between text fields and switches off when the keyboard restarts.

<SettingsPath path="Typing / Physical keyboard / F-keys press the toolbar" />

**F-keys press the toolbar** gives the function row the job of the <KeyCap>Ctrl</KeyCap>+number chord: <KeyCap>F1</KeyCap> opens all tools and <KeyCap>F2</KeyCap> to <KeyCap>F10</KeyCap> press the toolbar buttons from the left. On **In pick mode**, the default, the F-keys stay with the app until pick mode is on. **Always** keeps them all the time, which gets in the way of terminals and code editors. **Off** never takes them. While the F-keys work, the toolbar badges read `F1`, `F2` and so on.

### Chinese and Japanese candidates

Typing Chinese or Japanese, the candidate strip comes up on its own while a reading is waiting to convert, with the on-screen keys still hidden, and the keys work it the way a desktop input method does. The arrow keys move a highlight along the candidates, <KeyCap>Space</KeyCap> or <KeyCap>Enter</KeyCap> types the highlighted one, and once one is highlighted <KeyCap>1</KeyCap> to <KeyCap>9</KeyCap> pick by position and <KeyCap>Esc</KeyCap> goes back to the reading. To have the space bar step through the candidates rather than type the first one, turn on **Space steps through candidates** for that language. See [picking with space, the arrows and Enter](/languages/cjk/#picking-with-space-the-arrows-and-enter).

**Show the keyboard for shortcuts** covers the case where a physical keyboard is attached and there's no reason for the on-screen keyboard to be up. Press a shortcut that opens a tool and the keyboard comes up anyway, because the tool needs somewhere to draw. It hides again once you close the tool.

A related setting lives elsewhere. <SettingsPath path="Appearance / Toolbar / Only the toolbar with a hardware keyboard" /> hides the key grid entirely, leaving just the suggestion strip and toolbar, whenever a physical keyboard is attached. You're typing on the physical keys anyway. It's off by default.

### Show the keys again

With only the toolbar showing, a keyboard button sits at the far end of the toolbar. Tap it and the on-screen keys come back, for when the physical keyboard is folded away or out of reach. Tap it again (it now shows a hide-keyboard icon) and they go away. On the physical keyboard, the shortcut key and then <KeyCap>Space</KeyCap> does the same thing.

You don't have to put the keys away yourself. The next key you type on the physical keyboard hides them again, the way Gboard does. Shortcuts, arrow keys and modifiers don't count, only keys that type. If you'd rather keep the keys up until you tap the button, turn off <SettingsPath path="Appearance / Toolbar / Hide the keys when I type on the hardware keyboard" />.

The keyboard remembers whether the keys were up, so the next text box opens the way you left the last one. The button lives on the toolbar, so while suggestions fill the strip, tap the arrow to bring the toolbar back first.

## Details and edge cases

- **The tool picker waits eight seconds for a key** before it disarms itself. Adjustable from one to thirty under **Time to press a key**.
- **The badges never resize the keyboard.** They're drawn over the buttons rather than added beside them, so double-tapping <KeyCap>Ctrl</KeyCap> can't shove the app's text out from under your hands.
- **Toolbar badges only show when the toolbar does.** With suggestions occupying the strip instead, <KeyCap>Ctrl</KeyCap>+number still opens the same tools, with nothing on screen to label them. The cheat sheet lists them either way.
- **Reserved chords still work as a shortcut key, with a warning.** Capture a chord like Ctrl+C, Ctrl+V, Ctrl+S or Ctrl+Tab as your shortcut key and the picker warns you it's "usually the app's own shortcut", then lets you use it anyway. It's a nudge, not a block.
- **Process the physical keys only governs typed characters.** Turning it off stops physical keys from running through autocorrect and suggestions. Tool shortcuts, panel navigation and Esc keep working regardless, since none of them touch typed text.
- **No build differences.** Everything on this page works the same in every build.
- **Presence detection is automatic.** The keyboard notices a physical keyboard attaching and detaching through the system's own configuration, which is also what drives the separate "Only the toolbar with a hardware keyboard" setting above.

For the complete shortcut and cheat-sheet reference in one table, see [Hardware shortcuts](/reference/shortcuts/). For the toolbar setting that hides the key grid when a keyboard is attached, see [Appearance settings](/reference/settings/appearance/).
