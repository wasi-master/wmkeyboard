The Privacy screen is six groups, in this order: the way into the permissions inventory, learning on this device and incognito, Android's own backup opt-in, whether other apps may control the keyboard, whether downloads are checked against their checksum, and the one button that clears learned data. Nothing else. This page is the field reference. For the reasoning and the rest of the privacy story, start at [Privacy at a glance](/privacy/overview/).

## Options

<SettingsPath path="Privacy" />

### Permissions

<SettingsPath path="Privacy / Permissions" />

| Setting | Control | Default |
|---|---|---|
| Permissions | Opens a sub-screen | n/a |

An unnamed group holding three navigation rows, sitting above everything else on the screen. The first is "See what the keyboard can reach, and give or take back a permission". It opens the permissions inventory, which is a screen of its own and has its own page here, [Permissions](/reference/settings/permissions/). Nothing on this row is a setting, so there's nothing to reset.

### Network activity

<SettingsPath path="Privacy / Network activity" />

| Setting | Control | Default |
|---|---|---|
| Network activity | Opens a sub-screen | n/a |
| Keep a network log | Switch, on that screen | On |
| Show activity on the keyboard | Switch, on that screen | Off |

The second row opens the log of every request the keyboard makes: which feature, which server, how much data, and whether it happened by itself. It keeps addresses and sizes only, never what you typed. The whole screen, and exactly what it does and doesn't record, is on [Network activity](/privacy/network-activity/).

### App lock

<SettingsPath path="Privacy / App lock" />

| Setting | Control | Default |
|---|---|---|
| App lock | Opens a sub-screen | Off |

The second row in the same group: "Ask for your fingerprint, a PIN, a password or a pattern before the screens and the delete buttons that you pick". The right-hand side reads **On**, **Off**, or **Not available** when the lock uses the fingerprint and this phone has no fingerprint and no screen lock to check against.

It opens a screen of its own, where you turn the lock on, choose what it covers, and choose whether a fingerprint or a PIN, password or pattern answers it. Turning it on and turning it off both ask for a check. See [App lock](/reference/settings/app-lock/) for the full field list.

Before you turn it on, note that the lock hides screens inside the settings app, and it does not encrypt anything. An export file, the Android backup, USB debugging and a rooted phone all still reach the same data.

### Learning on this device

<SettingsPath path="Privacy / Learning on this device" />

| Setting | Control | Default |
|---|---|---|
| Learn from typing | Toggle | On |
| Add words to the system dictionary | Toggle, shown only while Learn from typing is on | Off |
| Use the Android dictionary | Toggle | On |
| Expand Android dictionary shortcuts | Toggle | On |
| Incognito mode | Toggle | Off |
| Follow private browsing | Toggle | On |
| Incognito by app | List of apps, each Always incognito or Never incognito, and Add an app | Empty |

**Learn from typing** is the master switch for the on-device word and word-pair lexicon. Turning it off stops new learning without deleting anything already learned.

**Add words to the system dictionary** also writes learned words to Android's own personal dictionary (System Settings → Languages & input → Dictionary), so other keyboards and the platform spell checker see them too. It's the one setting in this group that writes outside the app, which is why it defaults off even though the keyboard's own learning already covers the same ground. The row only appears while **Learn from typing** is on, since words reach the system dictionary through that same learning path.

**Use the Android dictionary** reads that same system dictionary the other way. Every word in it is a known word: it's suggested, autocorrect leaves it alone, and typing or gliding it never raises the "add to dictionary?" chip. The list is re-read whenever it changes, so a word added in System Settings works at once.

**Expand Android dictionary shortcuts** reads the shortcut column of that list. Type a shortcut you've defined there, say "omw", and it offers the full phrase, "on my way", as a suggestion.

**Incognito mode** and **Follow private browsing** are covered in full on [Incognito & secure fields](/privacy/incognito/), including exactly what pausing learning and clipboard capture means. **Follow private browsing** defaults to **on**, the opposite of its neighbour "Incognito mode". Two related toggles, **Pause learning** and **Pause clipboard capture**, both on by default, live on <SettingsPath path="Tools / Incognito" /> rather than here, next to a third, **Keep copies in the keyboard**, off by default, which keeps the keyboard's own copies off the system clipboard while incognito is on. "Follow private browsing" appears on that Tools screen too. It's the same setting shown in both places, not a second copy.

### Android backup

<SettingsPath path="Privacy / Android backup" />

| Setting | Control | Default |
|---|---|---|
| Back up with Android | Toggle | Off |

**Back up with Android** folds the keyboard into Android's own backup and phone-to-phone transfer system. It's off by default, so nothing this keyboard stores is copied anywhere until you turn it on. Once on, it includes settings, themes, layouts, snippets, learned words, sticker and icon packs, plugins, imported fonts and the word lists you imported yourself, plus any saved API keys (Translate, AI tools, and the rest). Voice and AI models, downloaded dictionaries, and emoji-keyword packs are left out, because the keyboard can fetch them again on its own. So are four smaller things, all for size: the camera and document-scanner scratch folders, the images behind clipboard entries (the clipboard's text history stays), and the uncropped originals behind your stickers (the stickers themselves stay). A cloud backup is only made on devices that can encrypt it with your screen lock.

<PhoneFrame side caption="The info dialog for Back up with Android, listing what's included and excluded.">
  <Shot id="reference/settings/privacy-backup-info-dialog" alt="The info dialog for Back up with Android, listing what's included and excluded." />
</PhoneFrame>

This is a different screen from the sibling **Backup & restore** item on the Settings home screen (route `backup`), which exports and imports a settings file by hand and never touches Google at all. See [Backup & restore](/privacy/backup/) for both paths side by side, and the [Backup & restore reference](/reference/settings/backup/) for that screen's own fields.

### Other apps

<SettingsPath path="Privacy / Other apps" />

| Setting | Control | Default |
|---|---|---|
| Let other apps control the keyboard | Toggle | Off |
| Allowed actions | Opens a sub-screen, shown only while the toggle is on | n/a |

**Let other apps control the keyboard** decides whether the keyboard listens to commands from `adb`, Tasker, MacroDroid and other apps that send Android intents. While it is off, it ignores all of them. Turn it on and **Allowed actions** appears under it, with the number of actions that are on at the right.

**Allowed actions** has one switch per kind of command, in two groups. The **Keyboard controls** are on by default: switch language and layout, apply a keyboard mode, change the theme, show and pin the keyboard, sound and haptics, power saving and data saver, size and position, open a tool, and turn incognito on. The **Needs more trust** group is off by default: turn incognito off, add and block words, back up now, announce layout changes, and type text. The commands behind each row, and how to send them, are on [Automation: adb and Tasker](/reference/automation/).

### Downloads

<SettingsPath path="Privacy / Downloads" />

| Setting | Control | Default |
|---|---|---|
| Verify downloaded files | Toggle | On |
| Download feature libraries (F-Droid edition) | Toggle | Off |
| Feature libraries (offline build) | Get the files, Import | — |
| Qualcomm NPU runtime (GitHub edition, phones with a supported Snapdragon) | Toggle | Off |

**Verify downloaded files** holds every file the keyboard downloads or imports to the SHA-256 checksum it was published with: Chinese, Japanese and Cantonese dictionary packs, Whisper, Whistle, Parakeet, Moonshine, Asr4All and Sherpa voice models, the FUTO Swipe glide models, the sticker cutout model, script fonts, add-ons, Rboard theme packs, Keyman layouts from the mirror, and app updates on the GitHub build. A file that doesn't match is refused and deleted, because it's either damaged or not the file that was published.

Leave it on. It exists for one situation: a file had to change on the server, your installed version still expects the old checksum, and the update that knows the new one hasn't reached you yet. Turning it off lets that version take the new file in the meantime. Turning it off asks you to confirm first, and while it's off the row's subtitle says so. Turn it back on once you've updated.

**Download feature libraries** appears only in the F-Droid edition. The GitHub and F-Droid editions leave the native libraries behind some features out of the app, and fetch each one the first time its feature needs it. In the F-Droid edition, those are offline voice typing, grammar checking and the built-in document scanner, among others. F-Droid allows an app to download code only when you opt in, so these features do nothing until you turn this on. You don't have to come here for it: a feature that needs a library shows a banner with **Turn on**, and once you confirm, its own **Download** button takes the banner's place. In the F-Droid edition and the offline build this group shows at every settings depth, though **Verify downloaded files** still appears only at Everything. Turning it on asks you to confirm, because F-Droid did not build or review those files. Each file is still checked against a checksum built into the app before it's used. You can also import the files yourself: copy them from the data repository's `natives` release, then use **Import** on the [Storage](/reference/settings/about/) screen.

**Feature libraries** replaces both rows above in the offline build, which has no internet permission and so can't download a library at all. Its subtitle counts the libraries on the phone out of all the build can use. **Get the files** lists each missing one by file name, size and address: a `<sha256>-<library>.so` on the data repository's `natives` release, or the vendor's `.aar` for Google's, Microsoft's and Qualcomm's libraries, which you import whole. **Import** opens the file picker. Each file has to match the checksum built into the app. See [The offline build](/privacy/offline/#feature-libraries).

**Qualcomm NPU runtime** appears in the GitHub edition on a phone that can run on-device AI on its NPU. The runtime is Qualcomm's, and the keyboard fetches it from Qualcomm's own package on Maven Central, so you accept Qualcomm's AI Stack License before the download. Picking **NPU** under Compute asks you the same thing. Turning this off withdraws your acceptance, and the NPU is no longer used.

Some checks stay no matter what. An app update still has to carry the developer's signing certificate, so an APK someone else signed is never installed. An add-on that runs code still has to publish a checksum at all. Models with a fixed file size (Whistle, the ExecuTorch voice models, the cutout model) still have to be that size.

### Your data

<SettingsPath path="Privacy / Your data" />

A single row, **Learned words**, with a **Delete the learned words** button that asks to confirm first. Confirming deletes thirteen files: your word and word-pair lexicon, the new words still waiting to be counted, your emoji-usage history, autocorrect's revert memory (which corrections you undid), your Chinese/Japanese/Cantonese pick history, and the language-mix tracker that remembers which language you tend to reach for. It also takes the hand and tap key-offset models that learn where your fingers land, what your own manual fixes taught autocorrect, your per-app language habit, the glide-outcome store that remembers which word you picked or undid, the glide-shape store that learns how you draw each word, and the word-rank file. The dialog names the first four, warns that your personal dictionary goes with them, and promises that your snippets and your imported word lists stay.

Your personal dictionary does go. The [Personal dictionary](/reference/settings/dictionaries/) screen edits the same word and word-pair lexicon file the keyboard learns into, so a word you added by hand and a word the keyboard picked up sit side by side, and this button takes both.

<PhoneFrame caption="Learned words, the only control in the Your data group.">
  <Shot id="reference/settings/privacy-clear-learned-words" alt="Clear learned words, the only control in the Your data group." />
</PhoneFrame>

This is the only bulk clear on this screen. Personal dictionary entries, clipboard history, and downloads each have their own per-item controls elsewhere. See [Your data on device](/privacy/data/#clearing-whats-stored) for the complete map of where every other category's clear control lives.

## Details & edge cases

- **"Delete the learned words" is one bulk action, not a per-category picker.** No dialog lets you choose which of the thirteen files to wipe. Confirming deletes all thirteen at once, with no undo.
- **"Follow private browsing" isn't two settings.** The row here and the row of the same name under <SettingsPath path="Tools / Incognito" /> both read and write `autoIncognito`; flip it in either place and the other reflects the change.
- **Saved API keys are included in an Android backup**, not excluded the way large downloads are. If that matters to you, use [Backup & restore](/privacy/backup/)'s manual export instead, which never leaves the device.
- **A cloud backup needs an encryptable screen lock.** On a device without one, turning "Back up with Android" on has nothing to back up into: Android's own backup system requires it.
- **The footer caption names the whole network side.** The screen's own note reads: "Typing works fully on this device. The word lists, prediction, autocorrect, transliteration and emoji search are part of the app, and none of them needs a network connection. The app collects nothing about you and has no analytics of its own. Handwriting, text scanning and QR scanning are built on Google's ML Kit, which reports its own diagnostics to Google while you use them. Only a tool uses the network, and only at the moment that you press it: translate, weather, web search, image search, GIFs, stickers, dictionary lookup and the AI tools. You can turn off each one of them on the Tools screen." See [Privacy at a glance](/privacy/overview/) for the same list with per-tool detail, plus the few fetches that happen without you pressing a tool.
- **Allowed actions keeps its switches while the master toggle is off.** Turning **Let other apps control the keyboard** off hides the row and blocks every command, but the choices under it are kept for the next time you turn it on.
- **Turning off "Verify downloaded files" is logged.** Each file it lets through despite a wrong checksum leaves a line in the debug log, so a bug report shows it happened.
- **No build differences.** Every setting on this screen behaves the same in every build.
