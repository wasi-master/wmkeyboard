The Key press screen collects everything about the physical act of pressing a key: vibration, sound, the preview bubble, timing, and press-and-hold shortcuts. This page lists them in the order they appear on screen. It's the field reference. For the reasoning behind each option, read [Sound & vibration](/typing/feedback/) and [Typing basics](/typing/basics/) instead.

## Options

<SettingsPath path="Key press" />

The screen has six groups, top to bottom: Haptic feedback, Key press sound, Key popup, Alternate keys, Timing, and Press and hold shortcuts.

### Haptic feedback

<SettingsPath path="Key press / Haptic feedback" />

| Setting | Control | Options / range | Default |
|---|---|---|---|
| Key press haptics | Toggle | On / Off | On |
| Haptic style | Choice (chips) | Tap / Key / Click / Heavy / Sharp / Custom | Tap |
| Haptic strength *(Custom only)* | Slider | 5–60 ms | 15 ms |
| Haptic intensity *(Custom, Sharp)* | Slider | 1–255, shown as a percentage | 255 (100%) |
| Press and hold haptics | Toggle | On / Off | On |
| Press and hold release haptics | Toggle | On / Off | Off |
| Vibrate on space *(shown only while Key press haptics is on)* | Toggle | On / Off | On |
| Vibrate on delete swipe *(same)* | Toggle | On / Off | On |
| Vibrate on key repeat *(same)* | Toggle | On / Off | On |
| Click on key repeat *(same)* | Toggle | On / Off | On |
| Follow the system touch feedback setting *(same)* | Toggle | On / Off | Off |
| Mute haptics in Do Not Disturb *(same)* | Toggle | On / Off | Off |

**Key press haptics** is the master switch. Turn it off and the six per-event rows below it disappear rather than grey out.

**Haptic style** picks how the buzz is produced. Tap and Key hand it to the platform's own haptic call, which is what stock keyboards use, so it follows the vendor's tuning and the system haptic-intensity setting. Tap asks for the keyboard-specific waveform most vendors tune, and it's the default. Key asks for the general button press. Click and Heavy use a hardware-tuned effect (Android 10+). Sharp plays a hardware click primitive whose strength follows the intensity slider (Android 11+). Custom drives the vibration motor straight from the strength and intensity sliders. A style a device can't produce falls back to a hardware Click, then to Custom.

Two of the per-event rows are odd ones out. **Click on key repeat** has nothing to do with vibration at all: it's the sound half of "Vibrate on key repeat", playing the key sound on every auto-repeat while <KeyCap>⌫</KeyCap> or <KeyCap>Space</KeyCap> is held, and it does nothing unless Key sound is on. **Follow the system touch feedback setting** isn't a per-event gate either. It hands the master switch over to Android's own touch-vibration toggle. It ships off, so turning off touch feedback in Android's sound settings leaves the keyboard buzzing. Turn this on if you expect the system switch to cover the keyboard too.

### Key press sound

<SettingsPath path="Key press / Key press sound" />

| Setting | Control | Options / range | Default |
|---|---|---|---|
| Key sound | Toggle | On / Off | Off |
| Sound style | Choice (chips) | Click / Standard / Pop / Thock / Chime / Custom / Sound pack | Click |
| Installed sound library *(Custom only)* | List + import | up to 30 installed sounds | Nothing installed |
| Installed sound packs *(Sound pack only)* | List + import | up to 20 installed packs | Nothing installed |
| Key release sound *(Sound pack only, and only for a pack that has key-up recordings)* | Toggle | On / Off | On |
| Sound volume | Slider | 5%–100% | 50% |

Seven chips, not six. Click and Standard come from the device's own system sound pack; Pop, Thock and Chime are synthesized in-app and sound identical on every device. The last two both name something you've installed rather than a fixed waveform, so each reveals its own list when you pick it.

Choosing **Custom** reveals your installed sound library and an **Import a sound file (.mp3)** button, and the label undersells it, since it also accepts `.ogg` and `.wav` files. The library holds up to 30 sounds between imports and installed sound addons.

Choosing **Sound pack** reveals a second, separate list with its own **Import a sound pack (.wmsoundpack)** button, holding up to 20 packs. A pack is one keyboard recorded many times over, up to 32 recordings, and the keyboard picks a different one per key press. Each pack's row says what it carries, so "10 recordings • keys sound on the way up" means the pack was recorded with key-up sounds as well. For those packs only, a **Key release sound** toggle appears under the list. It's on by default. Packs without key-up recordings don't show it, because there'd be nothing for it to do. Tap a pack in the list and it plays a full keystroke rather than just the way down. See [Sound & vibration](/typing/feedback/#sound-packs) for the longer version.

Installing a [Sound addon](/addons/overview/) highlights this **Sound style** row and offers to switch to it right after install, the same "Use it now?" flow other addon types use (see [Installing addons](/addons/installing/)).

### Key popup

<SettingsPath path="Key press / Key popup" />

| Setting | Control | Options / range | Default |
|---|---|---|---|
| Key popup | Toggle | On / Off | On |
| Popup on number pads *(shown only while Key popup is on)* | Toggle | On / Off | Off |
| Minimum popup duration *(same)* | Slider | 0–300 ms | 140 ms |
| Maximum popup duration *(same)* | Slider | 400–2000 ms | 750 ms |
| Popup on key | Toggle | On / Off | On |
| Popup font size | Slider | ×0.70–×1.60 | ×1.00 |
| Popup height | Slider | 32–160 dp | 110 dp on-key, 65 dp floating |
| Popup distance above key *(shown only while Popup on key is off)* | Slider | 0–96 dp | 10 dp |
| Popup sideways shift *(same)* | Slider | −64–64 dp | 0 dp |
| Popup shape | Nav row (shape picker) | the twelve key shapes | Rounded |
| Popup corner radius | Slider | 0–40 dp | 12 dp |
| Popup color | Color picker | any color, or Automatic | Automatic |
| Popup text color | Color picker | any color, or Automatic | Automatic |

**Minimum popup duration** keeps the bubble visible for at least that long after release, so a fast tap doesn't flash it for a single frame. **Maximum popup duration** is a safety cap rather than a comfort setting. It force-hides a bubble stranded on screen when the release event is dropped under UI lag. It's measured from the press, not from the release, and there's normally no reason to lower it. **Popup on key** switches between two looks: the bubble growing up out of the pressed key (the stock-keyboard look), or a compact bubble floating above your fingertip with a gap.

**Popup height** looks like one slider, but it stores a value per bubble style, because the two want very different numbers. An on-key bubble is measured from the bottom of the key it covers, so most of its height goes on climbing back out from under your finger. A floating bubble already starts above the key. Flip **Popup on key** and the slider shows the other style's height. A drag in one mode never resizes the other. A theme can carry its own popup height too, and when it does the theme wins over whichever value the slider holds.

**Popup distance above key** and **Popup sideways shift** place the floating bubble, and appear only while **Popup on key** is off. The distance is how far above the pressed key the bubble sits. Raise it when your finger covers the bubble, which is the usual complaint about the floating style, and the keyboard makes the same amount of extra room above the top row so a bubble there is still drawn in full. The sideways shift moves the bubble left (a negative value) or right (a positive value) of the key, which gets it out from behind the hand that holds the phone. It's a screen-space shift rather than a start-relative one, because it's about your hand and not about the script, so an RTL layout doesn't mirror it. Near the edge of the keyboard the bubble stops at the edge instead of leaving the screen.

**Popup color** and **Popup text color** are the bubble's background and the character inside it. Both read **Automatic** until you pick one, which means the bubble follows the keyboard theme. A color picked here wins over the theme, and the reset control on the row puts it back to Automatic. Unlike the shape and the radius, these two stop at the preview bubble: press-and-hold alternates, the language picker and the panel menus stay on the theme's popup color. A per-key style from a layout still overrides both.

**Popup shape** and **Popup corner radius** reach past the preview bubble. They set the outline of every popup surface the keyboard draws, press-and-hold alternates, the language picker and the panel menus included. The radius applies only to the rounded and cut shapes. The rest size their corners off the popup itself. A theme can override either one.

### Alternate keys

<SettingsPath path="Key press / Alternate keys" />

This group is about the press-and-hold popup, not the preview bubble above it. The two are different popups and they size separately.

| Setting | Control | Options / range | Default |
|---|---|---|---|
| Alternate key size | Slider | ×0.70–×3.20 | ×1.00 |
| Alternate key spacing | Slider | 0–32 dp | 10 dp |
| Alternate key columns | Stepper | Auto, then 3–11 | Auto |
| Closest to the key first | Toggle | On / Off | Off |

**Alternate key size** goes twice as far as **Popup font size** does, because the alternates popup grows to hold whatever you give it while the preview bubble has a fixed height to stay inside. If you'd already raised the popup font size before this slider existed, it starts at that value, so nothing shrank on you. From there the two are independent.

**Alternate key spacing** is the room around each character. It's both the gap you see and the target you tap, so raise it if you keep hitting the neighbour. A roomier popup is a wider one, and a wider one wraps onto more rows.

**Alternate key columns** is Auto by default, which fits as many per row as the screen allows and lets the popup's shape follow the width of the characters. Pick a number instead and every row gets that many equal columns, so a key with a dozen alternates reads as a block and each character stays where you last found it. The stepper walks Auto, 3, 4 and up to 11 one press at a time.

**Closest to the key first** decides which end of a multi-row popup the first alternate goes to. Off, the popup fills like lines of text: first alternate top left, and on a tall popup that's the corner furthest from your thumb. On, it fills from the key outward, so the first alternate sits on the row nearest your finger and the overflow climbs away. That's the AOSP behaviour, and it's the shorter reach on keys with long lists. On a one-row popup the two look identical.

### Timing

<SettingsPath path="Key press / Timing" />

| Setting | Control | Options / range | Default |
|---|---|---|---|
| Press and hold delay | Slider | 150–700 ms | 300 ms |
| Time before a key repeats | Slider | 150–800 ms | 300 ms |
| Delete repeat interval | Slider | 20–200 ms | 50 ms |
| Space repeat interval | Slider | 20–200 ms | 100 ms |
| Caps lock double press | Slider | 150–600 ms | 350 ms |

**Press and hold delay** is how long you hold a key before its alternates popup (accents, digits, symbols) appears. **Time before a key repeats** is the separate wait before a held <KeyCap>⌫</KeyCap> or <KeyCap>Space</KeyCap> starts repeating. The two used to share one number, so slowing down accent popups for a tremor slowed down backspace with it.

The repeat interval is two sliders, because delete and space are held for opposite reasons. **Delete repeat interval** sets how fast a held <KeyCap>⌫</KeyCap> clears text, and faster is usually better. **Space repeat interval** does the same for a held <KeyCap>Space</KeyCap>. A runaway row of spaces has to be undone afterwards, so that one is worth setting slower, and it ships slower: delete at 50 ms, space at 100 ms.

**Caps lock double press** is the window for two <KeyCap>Shift</KeyCap> taps to lock caps. It only matters on the way into caps lock. A single tap while Shift or Caps Lock is already on always turns it off, whatever the timing.

### Press and hold shortcuts

<SettingsPath path="Key press / Press and hold shortcuts" />

| Setting | Control | Options / range | Default |
|---|---|---|---|
| Press and hold hints | Toggle | On / Off | On |
| All accents on press and hold | Toggle | On / Off | Off |
| Press and hold ?123 for the number pad | Toggle | On / Off | On |
| Currency keys | Free-text field, space-separated | Any characters | ৳ € £ ¥ ₹ ₿ |
| Ctrl shortcuts as raw key events | Toggle | On / Off | Off |
| Press and hold A to select all | Toggle | On / Off | Off |
| Press and hold C to copy | Toggle | On / Off | Off |
| Press and hold X to cut | Toggle | On / Off | Off |
| Press and hold V to paste | Toggle | On / Off | Off |
| Press and hold Z to undo | Toggle | On / Off | Off |
| Press and hold Y to redo | Toggle | On / Off | Off |
| Shortcut keys *(shown once at least one of the six above is on)* | Nav row → dialog | one letter per action | a c v x z y |

**Press and hold hints** puts a small corner label on each key, previewing its first press-and-hold character. A key running one of the hold-letter shortcuts below shows no hint.

**All accents on press and hold** adds the complete accent set to every Latin letter's popup, on top of whatever the layout already lists. Letters only.

**Press and hold ?123 for the number pad** is on out of the box. Hold the symbols key and a full number pad panel opens over the current field. A quick tap still switches to the symbol layer as usual.

**Currency keys** is stored empty by default. The field shows and edits the built-in set (৳ € £ ¥ ₹ ₿) until you type your own space-separated list. Clear it back to blank and the built-in set comes back.

**Ctrl shortcuts as raw key events** only matters for a Ctrl key on a custom layout, whether you tap it or [drag from it onto another key](/typing/gestures/#dragging-from-a-modifier-key-to-fire-a-shortcut). Off, A/C/V/X route through Android's clipboard actions, which work in web pages and Compose apps too. On, the raw key event goes through instead. A terminal app needs that, since it reads Ctrl+C as interrupt rather than copy.

The six **Press and hold [letter] to…** toggles are all off by default, and each one replaces that letter's accent popup outright. Turn on "Press and hold C to copy" and `çć` leave C's popup entirely; the shortcut doesn't sit alongside them. Copy and cut both fall back to select-all when nothing is selected, so one hold copies or cuts the whole field.

**Shortcut keys** is one row for all six bindings rather than six rows, and it only appears once you've switched at least one of them on. The shipped `a c v x z y` is a QWERTY answer, so a layout without those letters (Bangla, Russian) needs the whole set moved onto keys it actually draws. The row's subtitle lists the keys currently bound. Tap it to open a dialog with one field per switched-on action, saved in one go.

## Details & edge cases

- **The six per-event toggles fold away rather than grey out.** With Key press haptics off, Vibrate on space, Vibrate on delete swipe, Vibrate on key repeat, Click on key repeat, Follow the system touch feedback setting and Mute haptics in Do Not Disturb all leave the screen.
- **Press and hold delay is duplicated in two places.** This Timing slider (150–700 ms) and a second copy under Accessibility → Touch both move the same underlying setting. The second one is framed for hand tremor and runs wider, 150–800 ms. See [Accessibility settings](/reference/settings/accessibility/).
- **A few rows on this screen aren't reachable from in-app settings search.** Haptic style, Click on key repeat, Follow the system touch feedback setting, Sound style, Key release sound, Time before a key repeats and Shortcut keys are all real, rendered rows here. They're just missing from the search index. Everything else is indexed, Key sound, Sound volume, Maximum popup duration, Popup shape, Popup corner radius and Press and hold ?123 among them.
- **Most rows here grow a restore button once you move them, but four never do.** Change a toggle, a slider or the Shortcut keys row and a small restore control appears beside it, putting just that setting back. The two chip rows (Haptic style, Sound style), the Popup shape picker and the Currency keys field are hand-built controls with no restore of their own. Clearing Currency keys back to blank is how you get its built-in set again. See [Putting one setting back](/reference/settings/#putting-one-setting-back).
- **The "Sound & haptics" toolbar tool isn't a separate settings surface.** Its panel reuses the same Key press sound group, plus a nav row into this full screen, so a change on either surface writes to the same settings. See [Sound & vibration](/typing/feedback/#a-toolbar-shortcut).
- **Currency keys shows the built-in default even though the stored value is empty.** The field only starts writing your own list once you edit it. Clear it back to blank and you get the same default again, not an empty popup.
- **No edition differences.** Haptics, key sounds, popups, timing and press-and-hold shortcuts all work identically on the full and lite builds.
