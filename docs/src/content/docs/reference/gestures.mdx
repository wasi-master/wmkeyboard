## Swiping the spacebar

<SettingsPath path="Typing / Gestures" />

Which action a spacebar swipe runs depends on *when* the drag starts relative to the press-and-hold delay (300&nbsp;ms by default), not on how far it travels. A drag that crosses the slop before the delay elapses uses the **Quick swipe on the spacebar** slot. One that starts after uses the **Press and hold, then swipe** slot. Full mechanics on [Gestures](/typing/gestures/) and [Switching languages](/languages/switching/).

| Gesture | Where | What it does | Setting |
| --- | --- | --- | --- |
| Tap, no movement | Spacebar | Types a space | None |
| Swipe starting before the press-and-hold delay | Spacebar | Runs the quick-swipe slot's action | Quick swipe on the spacebar (default Language) |
| Hold past the press-and-hold delay, then swipe | Spacebar | Runs the hold-swipe slot's action | Press and hold, then swipe (default Cursor) |
| Slot = Language, swipe sideways | Spacebar | Steps through enabled layouts (44&nbsp;dp per step, 110&nbsp;dp to wrap past either end) | Either slot set to Language |
| Slot = Cursor, swipe sideways | Spacebar | Moves the text cursor one character per 16&nbsp;dp of drag | Either slot set to Cursor |
| Same, dragging vertically | Spacebar | Also steps the cursor a line at a time | 2-D cursor touchpad (Off) |
| Slot = Numpad, cross the initial slop | Spacebar | Opens the numeric keypad (one-shot, so the rest of the drag does nothing) | Either slot set to Numpad |
| Straight downward drag, steeper than it is wide | Spacebar | Dismisses the keyboard | Swipe down to hide the keyboard (Off) |
| Press and hold (~250&nbsp;ms, or your press-and-hold delay if shorter), with two or more layouts enabled | Spacebar | Opens the inline language preview or a scrollable picker list | None |
| Drag once the preview or picker is open | Spacebar | Always switches language, regardless of which slot is configured | None |

## Dragging backspace to delete words

<SettingsPath path="Typing / Backspace" />

Tap, hold-to-repeat, and word-swipe are one state machine on <KeyCap>⌫</KeyCap>, so a drag can take over from the repeat loop mid-press. Each word costs less to delete than the last: 72&nbsp;dp for the first, 56&nbsp;dp for the second, then 6&nbsp;dp less per word down to a 28&nbsp;dp floor. Full breakdown, including the character-run and selection rules, on [Gestures](/typing/gestures/#deleting-whole-words-with-backspace).

| Gesture | Where | What it does | Setting |
| --- | --- | --- | --- |
| Tap | Backspace | Deletes one character | None |
| Hold still | Backspace | Repeats character deletion after the repeat wait, at the delete interval | Time before a key repeats · Delete repeat interval |
| Drag left past a small slop | Backspace | Cancels the repeat and deletes a word per step, shrinking with each word | Swipe to delete words (On) |
| Drag right mid-swipe | Backspace | Re-anchors instead of undeleting, so the next leftward word costs full travel again | (same) |

| Gesture | Where | What it does | Setting |

## Dragging from a modifier key

A <KeyCap>Ctrl</KeyCap>, <KeyCap>Alt</KeyCap> or <KeyCap>Meta</KeyCap> key only exists on a layout you built or imported, since none of the shipped ones carry a modifier row. Add one from the [layout editor](/languages/custom-layouts/#editing-a-key). Full mechanics on [Gestures](/typing/gestures/#dragging-from-a-modifier-key-to-fire-a-shortcut).

| Gesture | Where | What it does | Setting |
| --- | --- | --- | --- |
| Tap | A modifier key | Arms it for the next key you press | None |
| Double-tap | A modifier key | Locks it until you tap it again | None |
| Drag onto another key and lift | A modifier key | Sends that combination, then clears the modifier | None |
| Drag off and back, then lift | A modifier key | Arms it, the same as a tap | None |
| Drag off the key grid and lift | A modifier key | Cancels, and nothing is sent | None |

## Using the volume keys as a cursor

<SettingsPath path="Typing / Volume keys" />

Off by default, and only active while the keyboard is on screen. As soon as it closes, the volume keys go back to controlling volume. See [Gestures](/typing/gestures/#volume-keys-as-a-cursor-control) for the swallow-press-and-release detail.

| Gesture | Where | What it does | Setting |
| --- | --- | --- | --- |
| Press volume down | Hardware volume rocker | Moves the cursor one character left | Volume keys move the cursor (Off) |
| Press volume up | Hardware volume rocker | Moves the cursor one character right | (same) |
| Hold a volume key | Hardware volume rocker | Repeats via Android's own hardware key-repeat | (same) |
| Press while audio is actually playing | Hardware volume rocker | Falls back to real volume control instead of the cursor | Release the keys while audio plays (On) |

## Details & edge cases

- **The two spacebar slots resolve by hold time, not distance.** A fast flick and a careful drag can cover the same ground, so the keyboard can't tell them apart by how far you've moved, only by whether the press-and-hold delay has elapsed yet.
- **Numpad is a discrete action.** Unlike Cursor or Language, which keep responding for as long as you drag, a slot set to Numpad only needs the initial slop crossed once; everything after that is inert.
- **Two settings hide the keyboard on a downward swipe, two words apart.** "Swipe down to hide the keyboard" under Typing → Gestures applies to the spacebar. A separate "Swipe down to hide" under Appearance → Toolbar applies to the toolbar strip. Turning one on doesn't touch the other, and both ship off.
- **The 2-D cursor touchpad only claims the vertical axis once a drag has actually resolved to Cursor.** With the defaults (quick swipe = Language, press-and-hold swipe = Cursor), a fast downward flick within the press-and-hold delay is still governed by the quick-swipe slot and dismisses the keyboard rather than scrolling through lines.
- **Backspace's word-delete acceleration resets on a reversal, not on release.** Dragging right mid-swipe doesn't bring back a deleted word. It only means the next leftward word costs full travel (72&nbsp;dp) again instead of the shrunk amount.
- **Volume-key cursor control re-checks "is audio playing" on every key press**, not once at the start, so Release the keys while audio plays hands control back and forth live as playback starts and stops mid-typing.
- **Two press-and-hold delay sliders share one value.** The Key press → Timing slider ranges 150–700&nbsp;ms. The Accessibility → Touch slider for the same setting shows a wider 150–800&nbsp;ms range, but the stored value still clamps to 700&nbsp;ms, so dragging that slider to 800 silently snaps back once you let go.
- **The backspace repeat has its own wait, not the press-and-hold delay.** Holding <KeyCap>⌫</KeyCap> starts repeating after Time before a key repeats (300&nbsp;ms), which is a separate slider. Lengthening the press-and-hold delay for accent popups no longer slows backspace down with it.
- **A very wide screen can let the floating panel's resize grip briefly exceed its 500&nbsp;dp maximum mid-drag.** It snaps back the moment you release.
- **With TalkBack or another screen reader running, most drags above stop working unless you turn on gesture pass-through.** Set **TalkBack support** to **Gestures** under Accessibility → Screen reader. Then grant the "WM Keyboard gestures" accessibility service. Those two steps keep the spacebar cursor slide, the backspace word-swipe, glide typing, and handwriting alive underneath TalkBack's own touch exploration. Without that service granted, all four fall back to Explore-by-touch and don't respond to a drag. See [Accessibility overview](/accessibility/overview/#the-gesture-pass-through-service).
